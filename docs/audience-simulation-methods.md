# 受众发现、few-shot 与评论互动：方法研究与实施设计

2026-09-25。本文是研究与候选方法设计，不是已经完成的功能说明，也不是效果实验报告。与 [首轮研究及实现记录](audience-simulation-research.md) 配套阅读：前一份记录已实现的证据边界，这一份回答接下来应该怎样建立受众、模拟反应和组织互动。本文没有修改生产 prompt，没有运行付费模型实验。

## 研究结论

最适合本产品的路线不是“先编三个完整人设，再让他们辩论”，而是：从真实笔记和评论提取需求证据，形成可追溯的读者视角；为当前内容选择相关的历史反应案例；先独立模拟，再按明确的可见评论做条件性交流，最后把分歧转成创作建议。

这里的 few-shot 至少有三种不同作用。**方法示例**教模型如何提取需求、引用原文和保留未知；**行为案例**提供某种内容曾经引发什么真实反应；**合成人设种子**扩展可能的读者情境。只有第二种直接提供这个账号的观测依据。示例数量增加、角色更加生动或争论更加热闹，都不能单独证明受众模拟更准确。

我们应把“发现受众”具体化为“发现评论中有依据的需求与阅读视角”。现有数据不能支持识别完整粉丝群体：规范化评论没有稳定的评论者身份关联，也没有完整回复链和曝光记录。因此，不能把多条评论算成多个独立用户，不能从只包含发言者的样本推算沉默者比例，也不能宣称在复刻某个真实个人。

## Few-shot 怎样用于找到受众

### 先教方法，再提供账号证据

建议把 prompt 分成带明确来源标签的两块，而不是将全部内容混成“背景”。`instructionExamples` 是人工审阅的方法示范，不能成为账号证据；`observedEpisodes` 是真实历史材料，每条携带 noteId、commentId、时间和原文。合成情境另设 `hypothetical` 标记，不能混进前两者的计数。

下面是我们建议制作的示范类型，仅为说明方法而编写，不是真实评论，也不是已投入运行的 prompt：

| 教学用输入 | 希望模型学到的输出 | 明确不能推出什么 |
| --- | --- | --- |
| 笔记讨论留学费用；评论问“住宿和保险算进去了吗？” | 需求：费用口径完整；依据是这句追问。 | 不能推断发言者收入低、家庭条件或国籍。 |
| 笔记提供申请路线；评论问“非应届也能用吗？” | 需求：适用条件；当前经验背景未知。 | 不能直接认定对方已经毕业。 |
| 评论只有“蹲蹲” | 可能关注后续，但具体需求不可确定；保留 unknown。 | 不能硬分进“预算敏感”或“申请焦虑”。 |
| 同篇笔记有“步骤清楚”和“我的情况用不上” | 分别记录有帮助与适用性异议，可以共享同一需求标签。 | 不能用一个多数标签抹去少数异议。 |

这借鉴了 Writer-Defined AI Personas 的示范式反馈，但我们把教学目标改为“事实、解释、未知的边界”。示例需要包含正常、模糊、多义和反例，而不是全是模型最容易做好的正例。真人评论本身不包含沉默样本，所以即使教学示例允许“不评论”，也不能据此学习实际不评论率。[示例机制来源](https://arxiv.org/html/2309.10433v2#S3.SS3.SSS2)

### 从评论编码到读者视角

建议分两步，而不是直接让 LLM 总结三个角色。第一步给每条被选评论做多标签编码：表达的需求、明确说出的约束、内容理解、态度、无法确定的属性，以及逐字引用。第二步把这些编码聚合成可解释的视角，如“需要明确适用条件的读者”，而不是“23 岁、焦虑、收入有限的留学生”。标签表先由历史材料提出，再人工抽查、冻结；标注时允许 unknown 和多个标签并存。

每个视角保留支持评论、相关笔记、同类内部的不同态度和未解决信息。统计由代码计算，不能由模型凭印象填写；统计单位是评论或笔记，不是粉丝人数。一个评论可有多个需求，因此需求计数也不要求相加等于 100%。稳定的需求画像与本次选题相关的证据选择分开，不能为了待测选题重新发明一群“刚好喜欢它”的读者。

这是受 Proxona 启发的本地适配方案，不声称优于原论文。小样本时先用透明的标签归并，不强制固定三个聚类。UI 可以先展示少量最相关视角，但完整依据保存在分析结果中。角色选择同时考虑跨笔记覆盖、与待测内容的相关性及已有的不同观点，不能只按模型挑出的引用条数选前三名，也不能为了正反平衡凭空制造反对者。

### 行为案例要保留“看到什么，回应什么”

一条孤立的“太贵了”不足以支持预算型画像：它可能在评价学费、商品定价，也可能在反讽。我们建议使用 `历史内容片段 → 实际评论` 的成对案例，附上来源与可推断范围。内容过长时可以截取相关片段，但保留原文引用；若不能确定评论针对哪段，记录“对应整篇，触发位置未知”，不能补造触发句。

为待测内容选案例时，先按时间和账号过滤，再比较相关性，最后控制单篇笔记占用和重复度。小数据量先用词项/需求标签匹配或 BM25，不需要引入向量数据库。相关性检索是由 KATE、LaMP 启发的候选机制；“相关案例加跨笔记覆盖优于随机案例”仍是本项目待验证假设。[KATE](https://aclanthology.org/2022.deelio-1.10/)、[LaMP](https://aclanthology.org/2024.acl-long.399/)

研究时比较 0/2/4/8 个案例，并改变顺序，观察结论是否过度追随某一个例子。这里的数量只是探索网格，不是文献证明的最优配置。评估还应记录原句复制、泛化问题数量和无依据推断；若 few-shot 只是让输出更像样例，却没有改善留出问题发现，就不应宣传成“学到了受众”。

## 受众怎样独立模拟

建议把读者角色定义成一个有历史依据的观察视角，而不是全知的内容顾问。角色输入包括需求与未知项、被选中的行为案例，以及本次实际公开的标题/正文/已处理的媒体。创作者的意图、预设痛点、为什么这个选题适合受众等内部字段，不向读者泄露。只有标题时做概念预演；没有处理图片就不评论图片质量。

每个角色先独立输出简短结构化状态：理解了什么、是否相关、触发片段、仍不清楚的问题，以及 comment/no_comment/skip 行动和可空公开评论。它不需要展示长推理链，不应人人主动给出运营建议。把“读者会怎样表达”与“创作者应该怎样修改”拆开，后者交给最后的分析步骤。这样才有可能区分真实阅读阻力与模型习惯性的专业点评。

生成结果不是新的观测事实。角色在同一次运行中可以记住自己说过什么，但不能把模拟评论写回真实评论资产，或在下一次受众分析中当作账号历史。一个视角反复采样得到多个答案，只能用来研究模型敏感性，不能当成多个真人投票。上述最小记忆设计借鉴 Generative Agents 的状态连续性，但不照搬其完整架构。[记忆机制来源](https://arxiv.org/html/2304.03442v2#S4)

## Debate 怎样模拟，才不是强行开会

我们应将其产品含义定义为“评论区情境交流”：如果某个读者看到了这些公开意见，会不会追问、补充、反驳或保持沉默？这与多个模型合力求正确答案不同。后者可用于内部证据审查，不能拿来决定所有模拟读者最终该同意什么。[答题型 debate 的目标](https://proceedings.mlr.press/v235/du24e.html)

建议维持现有两阶段图，先改消息契约。第一轮全部独立完成，第二轮才开放可见的公开评论。每个角色拿到自己的先前反应、当前读者状态、被展示的评论及可回复对象。不能看到其他人的私下顾虑、尚未发生的回复或总结者的结论。发言、看到评论、愿意回复是三件不同的事：第一轮没有评论的人，仍可能被别人的问题吸引而开始回应。

每条公开消息有 messageId、作者角色 ID、round 和可选 replyToId。回复目标必须存在、时间在前，并在这个角色的本轮可见集合内。保留不回复、保持原看法、部分改变和仍然不确定；若报告观点改变，需要指出哪条已见消息触发了哪项变化，而不是要求每个人都被说服。这是受观点动力学的接收者/状态模型和讨论 scaffolding 的结构约束启发的组合，尚未验证其模拟效果。[观点更新](https://aclanthology.org/2024.findings-naacl.211/)、[讨论结构](https://arxiv.org/html/2408.08379v1#S4)

研究版先比较三种条件：不互动、所有公开评论都可见、有限可见且保留自身状态。有限可见可以采用固定可复现的轮转安排，不把它包装成小红书推荐算法或真实浏览概率。一个回复回合足以先测试价值；增加第二回合应有新问题被发现的证据，而不是为了增加戏剧效果。没有可见消息、无人继续公开发言或达到预算时结束。

不要事先写好“甲反对、乙说服甲”的完整剧情。可以规定谁有机会看见哪条消息，但观点方向与是否回复由角色根据输入生成。这个约束是我们相对完整内容脚手架的设计选择，需要与更简单方法对照。缺乏真实回复链时，只能检验状态一致性、消息有效性与创作者效用，不能宣称还原真实评论互动分布。

## 我们可以尝试的优化

| 候选优化 | 对现状的具体改变 | 成立所需的证据 |
| --- | --- | --- |
| 需求编码后生成画像 | 替代一次性角色概括；保留 unknown、多标签和引用。 | 人工核验更容易；减少无依据属性；输入顺序变化时仍能识别主要需求。 |
| 以内容—反应配对作为 few-shot | 替代只给角色摘要或散落引文。 | 在相同 token 预算下，更好发现留出评论里的问题，而不是更多复读。 |
| 相关性加覆盖约束选案例 | 不让某篇热门笔记或一种态度占满上下文。 | 相比随机及单纯相关性检索，提高有效问题覆盖且不增加无依据判断。 |
| 保留自己的上一轮状态 | 第二轮不是重演一次新角色，而是对可见消息作回应。 | 减少自相矛盾、无缘由改口和回复错对象。 |
| 静默读者也可后续加入 | 不以“自己已评论”作为看到别人的评论的前提。 | 确定性测试验证可达；真人评审判断情境是否有用，不能据此估计转化率。 |
| 分开审查器与受众 | 内部审查器核对引文和总结是否过度外推，不让它替读者达成共识。 | 人工核验支持性提高；若额外调用不增益，就只保留代码校验。 |

这些是有文献启发、面向本产品的工程假设，不是已经成立的学术创新。尤其要避免把两个模块的效果混起来：独立反应改善不证明 debate 有效；引用通过校验不证明画像解释正确；用户喜欢结果也不等于真实发布效果变好。

## 怎样做对照实验

先沿用已有离线切分脚本，将目标笔记的评论和互动结果放在答案侧。所有画像、标签表和案例池只能使用允许的历史材料；人工教学示例属于独立的开发集，不得从测试答案挑选。开发时确定案例数量、排序、视角选择和停止条件，冻结后再看测试结果。重复内容清理规则也预先固定，不根据某条件的成绩来调整。

采用逐步消融，而不是一次排列所有组合：

1. **建立可比较基线。** 冻结旧版 prompt、schema、代码版本和输入快照；比较普通评审、同证据直接评审、当前证据化角色预演。旧文中的 E 必须指向固定基线，不能随主分支变化。
2. **只测 few-shot。** 固定模型与检索材料，比较无教学示例、有教学示例，以及再加入实际行为案例；同时做相近 token 预算对照，区分格式收益、信息收益和额外费用。
3. **只测案例选择。** 保持数量和预算，比较随机、相关性、相关性加跨笔记覆盖；比较孤立评论与内容—评论配对。顺序扰动只作为稳定性测试，不能增加真人样本数。
4. **最后测交流。** 在相同独立反应上分叉无交流、全可见、有限可见且有自身状态三种条件；后两者给相近调用预算。追踪新增的有效问题、错误判断、无依据改口和成本。

主要评价是留出评论的需求/疑问命中与错误警报，不以评论文字相似度为主。未出现在有限样本中的问题先标“未观察到”，不要直接认定是假；由人工进一步判断其依据与价值。画像侧评证据解释、unknown 使用、跨笔记覆盖和归并稳定性；互动侧评引用/回复有效性、自身状态一致性和新增信息；产品侧盲评建议是否具体、有新意、值得采用。模型裁判只能辅助，不能让生成模型自己打分作为唯一结论。

现有两个账号只能做方法试跑，不能证明跨账号泛化。统计单位应为账号或被留出的笔记，不是生成的评论条数；少量案例报告逐例结果，不包装显著性。评论样本无法验证沉默、收藏或划走概率，缺少回复链也无法验证互动网络。后续少量人工标注与真实一级/二级回复链，优先于继续增加模拟角色。

## 对应到当前代码的实施顺序

本文不要求重写 LangGraph、不新增通用 agent 平台、不添加向量数据库或版本表。保留现有运行记录、快照、断点、部分失败与前端历史；方法版本、示例集哈希和抽样策略可随运行快照保存。

当前代码的明确差距是：没有经过审阅的 few-shot 示例集；历史行为没有以内容—反应案例组织；前三组按引用覆盖简单排序；第二轮仅允许第一轮发过公开评论的角色参与，并且未显式传入自己的第一轮反应。此前已完成的证据校验、允许不评论、只暴露公开评论等应保留，不能因新方法而回退。代码依据：[证据服务](../backend/app/services/audience_evidence.py)、[分析服务](../backend/app/services/audience_analyses.py)、[模拟图](../backend/app/workflows/audience_simulation.py)。

确定性测试能覆盖：示例来源隔离、未知属性、时间切分、引用匹配、同账号边界、消息可见性、回复目标、静默后参与、失败与恢复。模拟是否准确、有用，必须靠真实模型输出与人工/留出数据评价，不能用单元测试通过替代。

## 下一步与需要参与的决定

建议先完成第 1 步，建立少量人工可审阅的方法示例和冻结的基线，再做小规模 Qwen 对照；不先上微调，也不先接大型社交模拟框架。真实 API 实验前确定费用/调用上限；实际效果对照完成前不默认开启更多轮次。

需要产品方后续参与的是审阅少量需求标签与匿名结果，以及是否能提供少量带上下文的真实回复链。暂时没有回复链不阻碍独立反应实验，只限制我们对 debate 真实性的结论。几个人设、几个 few-shot、几轮对话应由实验决定，不必现在拍板。
