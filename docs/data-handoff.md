# 把现有数据交给协作者

推荐方式：**代码走 Git，数据包私下发送。** 不需要把整个项目和 MediaCrawler 环境打成几个 GB 的压缩包，也不必让协作者重新抓取所有账号。

本文用于交付已导入的账号与作品。如果要保留原始抓取输出、离线样本等完整开发现场，另看[完整恢复说明](local-installation.md#4-恢复现有现场而不只是空白安装)。

## 数据包里放什么

| 内容 | 默认位置 | 是否打包 |
| --- | --- | --- |
| 账号、笔记正文、评论、选题、分析与对话历史 | `data/app.sqlite3` | 是 |
| 封面、上传文件和其他已导入媒体 | `data/uploads/` | 是；只传数据库会导致图片打不开 |
| 模型配置与 API key | `.env.local`、`backend/.env.local` | 默认不含；双方明确约定共用密钥时才加入 |
| MediaCrawler、Python 环境、Node 依赖 | `data/external/`、虚拟环境、`node_modules/` | 不含；需要时在对方电脑安装 |
| 小红书登录态 | 浏览器配置目录 | 不含；对方重新扫码 |

协作者只查看和继续使用现有资产时，不必安装 MediaCrawler；只有继续通过主页 URL 读取笔记时，才需要[安装抓取依赖](local-installation.md#2-安装抓取依赖)。

## 1. 原电脑打包

先等待抓取、分析、生成任务结束，正常停止后端及其抓取进程，再执行以下命令。不要在后端仍写入时复制 SQLite 主文件。

以下命令都在**仓库根目录**运行，使用默认数据路径。若配置了 `DATABASE_PATH` 或 `UPLOAD_DIRECTORY`，先按实际路径核对；默认包不会包含仓库之外的数据。

```bash
git rev-parse HEAD
tar -czf ../SqsAgent-creator-data.tar.gz data/app.sqlite3 data/uploads
tar -tzf ../SqsAgent-creator-data.tar.gz
```

记录第一条命令输出的代码提交号，与数据包一起交给对方。尚未提交的代码不会包含在该提交中，也不会随数据包一起交付。

如果停止服务后仍有 SQLite 的 `app.sqlite3-wal` 等配套文件，不要只传主文件；按[完整现场备份](local-installation.md#原电脑准备)保留配套文件。上述命令不会自动停止任何进程，也不是运行中数据库的在线备份。

输出文件位于仓库的上一级目录。使用只对协作者开放的渠道发送，如微信文件或私密网盘；不要上传到公开链接、Git 或聊天群。包内包含笔记、评论和创作历史，应按私人资料处理。

### 可选：一起交付模型配置

默认命令**不包含密钥**，对方可以[配置自己的模型](development.md#模型配置)。如果双方明确约定共用密钥，可把实际使用的 env 文件按原相对路径加入私下交付包。例如，配置仅在仓库根目录时：

```bash
tar -czf ../SqsAgent-creator-data-with-config.tar.gz \
  data/app.sqlite3 data/uploads .env.local
```

如果配置在 `backend/.env.local`，将最后一项改为该路径；两处都使用时加入两份。只写实际存在的文件，不要夹带浏览器 Cookie。这个包包含可用凭证，只交给约定的可信协作者，不提交 Git。

交付前核对配置中的绝对路径。新机器需要调整 `DATABASE_PATH`、`UPLOAD_DIRECTORY`、`XHS_CAPTURE_DIRECTORY`、`XHS_MEDIACRAWLER_DIRECTORY`、`FFMPEG_PATH` 等本机路径；如设置了 `DEFAULT_USER_ID`，保留原值，以免原数据不属于新环境的默认用户。

## 2. 协作者恢复

先按[本地安装指南](local-installation.md#1-获取主应用)安装主应用，使用与打包时相同或兼容的新版本，**先不要启动后端**。查看已有数据不需要先安装抓取环境。

将收到的压缩包放到仓库上一级目录。以下以不含配置的包为例；含配置包使用对应文件名。

在仓库根目录先检查内容：

```bash
tar -tzf ../SqsAgent-creator-data.tar.gz
```

确认来自可信协作者，内容是预期的 `data/` 路径；含配置包另有约定的 env 文件。**已有自己的数据库、上传文件或配置时，先停止服务并另行备份，不能直接覆盖，也不能通过解压合并两个数据库。**

确认后再恢复：

```bash
tar -xzf ../SqsAgent-creator-data.tar.gz
```

核对模型配置和本机路径，然后按[启动步骤](local-installation.md#3-启动与验证)分别启动后端、前端。后端启动时会应用尚未执行的数据库迁移；不要使用比备份时更旧的程序打开较新的数据库。

## 3. 确认恢复成功

- 账号列表与预期一致，切换账号后笔记不混淆。
- 笔记正文和封面都能打开；只有文字正常通常说明上传目录没有一起恢复。
- 选题、创作内容、分析、模拟及对话历史可以重新打开。
- 按需检查模型连接；真实调用可能产生费用，命令见[开发与验证](development.md)。

无需为了验证数据恢复而重新抓取全部账号。新的抓取登录由协作者在自己的电脑完成；原电脑尚未结束的任务也不保证能跨机器接着跑，因此请在打包前等任务结束。
