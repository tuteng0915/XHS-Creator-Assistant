# 创作者工作区：笔记选择与单助手创作改造

初稿：2026-10-10；状态核对至 2026-10-11。已实现导航后移、账号／受众推导中的作者评论排除、单助手与分析／原笔记参考、左聊右稿、输入暂存、统一笔记选择及已有数据时间展示；账号报告已完成阅读层改造，并默认使用分阶段增强流程。完整字段级合并、采集端观察时间及内容质量改进仍待继续，不把工程验收视为模型质量全部通过。依据实际试用反馈整理；与旧方案冲突时，以本文和 PRD 最新决定为准。

本轮目标是让作者清楚知道“数据是哪一次的、这次选了什么、助手参考了什么”，同时把账号分析写得更具体、更有用。保留现有档案、作品、读者与历史，不重做通用 Agent 平台。

## 一、已确认的产品方向

1. “我的笔记”标题旁显示一行灰色的数据时间说明。
2. 选择笔记不只看时间，还能选最高赞、最高互动的前 N 篇；各入口复用同一套选择与预览体验。
3. 重新导入同一笔记应更新互动与评论，不重复建笔记，也不能把旧的有效信息抹掉。
4. 作者自己的评论不应当作读者需求；优先排除其分析用途，而不是删除原始记录。
5. 创作助手改为左侧聊天、右侧选题／正文；公开创作不再使用研究、写作、审稿三个专家接力。
6. 使用一个创作助手，由作者明确添加本次参考的分析记录等材料；不默认带入全账号历史。
7. 选题库和 AI 创作助手移到导航最后，排在受众分析、模拟粉丝和受众模拟之后。导航顺序不是使用门槛，仍可直接创作。
8. 账号分析融合旧版的具体写法拆解与新版的账号认识、指标依据；减少折叠及重复的防御性说明。

前三类页面仍各司其职：账号分析认识账号，受众分析产生可收录人物，受众模拟听取不同反应；创作助手负责讨论和改稿，不取代受众 Panel。

## 三、笔记数据时间与更新

### 3.1 时间怎么展示

“我的笔记”与时间同行，辅助文字 12–13px、次灰色；窄屏自然换行，不另起一张提示卡。

- 所有展示笔记具有同一批可靠观察日期：`数据截至 2026-10-10`。
- 只更新了部分笔记：`最近更新 2026-10-10 · 各篇时间见详情`，不能暗示全账号都更新到当天。
- 只有旧导入时间：`导入于 2026-10-09`；完全未知则显示 `暂未记录更新时间`，不拿今天或材料编辑时间补造。
- 点开笔记后，在指标旁显示该篇指标日期；评论有独立日期时显示评论更新时间。发布时间仍是发布时间，不混用。
- 分析和模拟历史继续显示当次冻结的数据时间，不随最新抓取变化。

页面已能读取 `metricsObservedAt`、`commentsObservedAt`；采集端持续提供这些观察时间及覆盖状态仍待补齐。观察时间应由获取数据的链路提供；部分指标未获取时需保留其旧时间或逐字段来源，不能更新整篇时间后冒充所有指标均为新值。批次 importedAt 仍记录导入事件，不取代观察时间。

### 3.2 相同笔记怎么更新

已先完成两项缺陷修复：线上与离线包更新时，同稳定 noteId 没有返回评论则保留旧评论及其作者标识／观察时间；评论 `likeCount`／`subCommentCount` 的合法 0 按原值保存。本轮不实现下面全部合并规划，非空新评论样本仍替换旧样本；缺稳定身份的旧位置 ID 不猜测匹配，不自动恢复已丢失数据。

以平台账号身份＋noteId 匹配当前材料，不以标题匹配。合并规则用于在线重抓；离线包更新应复用同一逻辑并保留其来源时间。

- 本次实际取得的指标覆盖旧值，包括合法的 `0`；缺失字段不改旧值。新值比旧值小也允许，不强取最大值。
- 旧批次不能覆盖更新的观察值；时间不明的离线包不静默替代已有较新数据。
- 评论按 commentId 更新已有项、追加新项。相同正文的不同评论不合并；缺稳定 ID 的记录只采用明确的保守去重规则，不凭文本推断是同一个人。
- 未请求评论、抓取失败、只取得一部分评论，均不得清空旧评论。返回空数组本身不证明原评论已删除；只有明确删除／完整性证据才另行处理删除语义。
- 正文和媒体也区分“本次没取得”与“确实变为空”；不能因新包缺封面而删旧封面。
- 本次未抓到的笔记保持原内容和观察时间。已保存分析、候选与模拟快照不回写。
- 完成回执用 `新增 X 篇 · 更新 Y 篇`，不把处理数量当新增数量。

数据合并必须先完成归属核对，再原子写入。此次不扩展为自动定时抓取，也不为了验收触发远端抓取。

### 3.3 作者评论：推荐的处理方式

采用“保留原记录、默认排除读者分析”的方案。

- 使用现有 note/comment `authorHash` 匹配确定作者；平台明确作者标记可作为经适配器规范化后的依据。不靠昵称相同、语气或提到“我”来猜。
- 笔记详情默认隐藏已识别作者评论，提供简洁的“显示作者回复”开关；展开时保留作者标记和回复关系。
- 账号分析的读者痛点和受众推导输入已统一排除作者评论；受众调用也不再发送独立的作者回复背景。先过滤再截取读者样本，旧重放和待执行账号快照同样适用；作者排除 ID 只留服务端核验，不进入模型输入。
- 身份未知的历史评论保留未知，不冒称一定来自外部读者；旧分析不批量重写。
- 平台评论总数维持平台值；页面另显示的是已采集／正在查看的评论数量。隐藏作者评论不能改平台互动量。

这能排除已识别的作者发言，同时保留作者补充解释供查看。历史数据缺作者标识时无法全部自动识别；不为补标记默认重新抓取。

## 四、统一笔记选择器

### 4.1 同一套操作

本节已实现：我的笔记浏览、账号诊断、受众分析、账号级模拟多选、已发布笔记单选及创作原笔记参考共用组件。自定义 N 位于选择弹窗，普通浏览提供 10／20／50。具体 ID 随请求冻结；受众新协议使用 `selected_notes`，账号级模拟使用 `accountNoteSelection`，创作使用逐篇 `imported_note` 引用，旧后端明确拒绝，不静默忽略选择。

扩展现有选择器，不再为每个页面复制一份列表：

- 范围下拉：全部已导入、最近 N 篇、最近 7／30／90 天、点赞最高 N 篇、互动最高 N 篇。N 提供 10／20／50 及自定义正整数，少于 N 就取实际可选数量。
- 支持单篇勾选、多篇选择、全选、反选、取消选择；显示已选数量，确认前不发起分析。
- 单选模式隐藏全选／反选，始终最多选一篇；保留排序、取消选择与预览。它复用同一组件，不继承不适用的多选操作。
- 卡片统一显示封面、标题、发布时间、赞藏评等指标；点卡片预览，不同时切换勾选状态。
- 详情能看正文和已保存的图片。已有封面先复用；多图需要补媒体关联，没有图片时用占位，不触发新抓取、不引入图片理解。
- 弹窗内选择是暂存状态；“完成”才交给调用页，“取消／Escape”保留调用页原选择。重开能恢复已经确认的具体笔记。

建议把范围和排序规则单独做成可测试的共享模块；选择器只管理选择与预览，调用方决定用途和单选／多选。

### 4.2 排序和选择语义

以下为实施默认值，不再给作者增加一套复杂配置：

- 全选／反选作用于当前筛选结果全集，不仅当前屏幕或分页；按钮或紧邻数量写清当前范围。取消选择清空本次已选集合。改变筛选用于查看候选，不暗中删除范围外已选项；快捷“选前 N 篇”明确替换本次选择，并可继续手选调整。
- “最高互动”按**已记录互动量**排序：点赞、收藏、评论、分享中实际取得的数值之和，不是互动率或内容质量分。至少有一个有效指标即可参与；缺失不写成 0、不估算，仅不计入本次和。四项全部未知的笔记不参与快捷排名，但可手选。数值由程序计算，模型不参与排序。
- 下拉附近用一句“按已记录赞、藏、评、分享排序”；有缺失时轻量注明“部分数据未获取”，不出警告卡，也不把部分和称为完整总量。排名快照记录参与指标与缺失字段，分析时仍逐项使用原值。只读检查显示一粒鱼 10 篇里仅 4 篇四指标齐全，QSheep 30 篇里仅 21 篇齐全；若强制完整才可排，会无谓缩小用户选择范围，因此不采用这一限制。
- 合法 0 参与排序；负数、非法值视为缺失。并列先按发布时间新到旧，再按稳定 noteId，保证恰好最多 N 篇且前后端一致。时间范围不纳入未知日期或未来日期；“全部”仍可手选这些笔记。
- “最高赞／互动”仅指已导入的候选集合。抓取页的“最近 N／全部可见”是远端获取范围，不承诺不用读全账号就能找出远端 Top N。
- 提交时保存具体 noteIds、排序规则及数据快照；重新打开历史不根据今天的指标重新挑人／挑笔记。

### 4.3 接入范围

| 入口 | 模式 | 约束 |
| --- | --- | --- |
| 我的笔记 | 浏览＋排序／筛选 | 不为浏览强加提交选择按钮 |
| 账号诊断 | 多选 | 复用现有手选能力 |
| 受众分析 | 多选 | API 补 selectedNoteIds，前后端使用同一最终集合 |
| 账号级模拟 | 多选 | 先确认具体集合，推荐与模拟同范围，不自动回填全账号或抽取 12 篇 |
| 已发布笔记级模拟 | 单选 | 共享封面与详情预览，不变成一次多篇试读 |
| 创作助手添加原笔记 | 多选 | 初始不勾选，每篇占一个参考名额，与分析历史合计最多 8 份；超限禁用完成，不静默裁掉 |

“所有筛选复用”指笔记材料选择。账号档案、历史记录、模拟读者仍有各自的数据和选择语义，不将它们强塞成同一种笔记卡。

账号级模拟初始无确认范围，弹窗内最多建议最近 10 篇，完成后显示“已选 N / 总数 篇笔记”。取消保留原集合及采用状态；同集合换顺序不作新输入，换集合／来源清除旧推荐采用与本次角色调整。所选笔记被删除时必须重新选择；只改未选笔记或增删未选项不影响推荐有效性。

显式范围包含全部所选笔记，每篇标题＋正文最多节选 1,200 字；目标超过 48,000 UTF-8 字节明确失败并要求减选，不静默裁掉笔记。简介不使用爬虫从全账号拼成的 `profileText`。推荐和模拟共用目标与内容版本，历史保存当时集合和节选；总体篇数只作范围展示，不参与所选内容的推荐过期判定。新入口不发送旧 `accountProfileId`，旧后端不能悄悄按原 12 篇执行；旧 API 和历史仍保留原兼容语义。本轮不改变模拟仅阅读作品文字的口径，不加入历史评论。

## 五、单创作助手与用户控制的参考材料

### 5.1 页面和导航

本节首批交互已实现；尚未完成的部分在 5.5 单列。

导航调整为：账号概览／我的笔记 → 账号诊断／分析历史 → 受众分析／模拟粉丝／受众模拟 → 选题库／AI 创作助手。

桌面主工作区：**左侧对话，右侧稿件**。对话顶部为“参考材料 ＋”和已经选择的短标签；右侧继续编辑标题、正文并保存。移除三个专家头像、“先交给哪位伙伴”、角色转交和类似群聊的专家回复关系。受众 Panel 的多人讨论不受影响。

左右调换已同步 DOM／键盘顺序、可拖动分栏、文字提示与窄屏布局。900px 及以下采用“对话／稿件”双页签，两边保持挂载、保留输入和滚动位置；不用滚过整篇稿件才能找到输入框。

保留“先聊角度／帮我起草”快捷动作、选段精修、建议预览、人工采用和保存。等待显示真实运行状态与耗时；有可交付片段就分段呈现，不展示隐藏推理、不伪造多阶段进度。

### 5.2 作者决定参考什么

固定输入只有：本轮要求、当前稿件、当前有效上下文段内的对话，以及必要系统写作规则。当前稿件始终可见，不能在幕后另加“账号全部历史”。

“添加参考”先选类型、再选具体记录，可多次添加、同类多份、去重和移除：

1. 账号分析历史：显示日期、选中笔记范围和概要，选择的是某一次结果。
2. 受众分析历史：显示日期、范围与人物概览；候选仍是模拟人物，不因作为参考就自动收录。
3. 已导入笔记：使用统一笔记选择器，作为正文／风格素材。
4. 受众模拟反馈：用户从群聊带入的特定意见作为显式参考项，不连带加入其他群聊或模拟历史。

前三类已经接入；特定读者意见仍通过已有 `writingFocus` 入口，不连带读取整场讨论。材料预览显示内容范围；不会自动沿来源关联递归添加整份档案。记录里的选题建议不等于本次已选择的创作方向。

默认不选任何额外材料，允许只靠稿件和聊天创作。重新打开同一篇可恢复作者的参考集，但新选题不继承其他选题的参考集，也不自动追踪“最新分析”。原笔记发送时读取所选 ID 的最新已保存标题／正文；若原文变更，建立新对话段。历史分析仍指向明确的某一次记录，不自动替换为最新分析。

### 5.3 上下文契约与切换

已新增 `creatorContextSelection`（`creator-context-selection/v1`），包含同账号引用列表；单助手发送时必须显式提供，空列表合法。服务端解析并冻结 `creatorContextSnapshot`（`creator-context-snapshot/v1`），记录类型、来源 ID、内容哈希版本、范围、内容、生成来源及必要时间信息。会话在既有初始快照记录 `assistantMode`，无需迁移表；旧调用方默认 `legacy_team`，公开前端明确创建 `single_writer`。

- 服务端只解析所选资料；不请求宽泛 workspace pack 后再寄希望于模型忽略无关内容。
- `creator_context.py` 精确读取已完成的账号／受众分析；账号仅投影 profile／pain_points，不读取后续选题或原材料。保留现有证据验证，不把 selectors 当过滤实现。
- 原笔记引用为 `{kind: "imported_note", id: 来源材料 ID, noteId: 笔记 ID}`，同一来源下多篇身份独立。只解析当前账号的确切唯一笔记，输入为完整标题／正文，不带评论、互动指标、图片或全账号简介；图片仅用于作者预览。不接受缺 ID、歧义 ID、`note-N` 位置兜底或标题正文均空的资料，不按标题猜匹配。原文不节选，仍计入总参考字符上限。
- 引用不存在、跨账号或内容过期时，在模型调用前给可处理的错误；不偷偷换成最近一次记录。
- 最多 8 份参考、48,000 序列化字符；超限说明需要减选，不静默删掉作者已选资料，也不后台全量扩展来源。
- 每次发送冻结参考集与稿件版本。运行中切换材料不改变已经发出的请求，返回结果标记其原参考集。
- **增删／替换参考集建立新的 context revision**：保留旧对话供查看，但旧段的助手总结和基于已移除资料的消息不自动带入新段。只传当前段最近 12 条消息；参考 A→空→A 不复活第一段。尚无一键引用旧消息，作者可主动复制所需内容发送；不把历史摘要当绕过选择的通道。
- 所选原笔记标题／正文更新也开启新段；仅指标、评论、导入时间或未选笔记变化不清空当前段。旧运行始终使用发送时的冻结原文，刷新导入不回写历史。
- 当前稿件仍是固定输入；换参考不会自动删除稿件中原有文字，也不宣称能抹去作者已采用的旧内容。

界面只需“本轮参考”及必要的变更回执，不把内部快照、指纹和协议铺给作者。

### 5.4 执行方式与复用边界

新创作请求走一个创作 Agent，不再 research → writing → review 自动接力。继续默认 Qwen；复用 session/message/run 持久化、异步等待、幂等、错误恢复、选段定位和人工采用，不另造一套调度系统，也不卸掉受众 Panel 使用的基础设施。

现有会话服务已增加单助手执行类型，以同一个 graph／writing 节点执行一个生成回合；不改旧角色枚举，不迁移旧历史。框架保留，公开新创作不再使用多角色路由。内部确定性校验继续运行，不以校验名义偷偷恢复三专家模型调用。

不直接恢复旧 `agent_conversations` 公开链路：它也存在自动读全局上下文和默认 demo 的旧语义。可借鉴其中讨论／起草／局部改稿／风格检查的输出方式，不能把旧默认行为一并带回。

旧单助手与多角色历史继续按原身份、原快照可读；继续创作时进入新类型会话，不改写旧发言。AI 建议必须预览后采用，保存与版本冲突保护保留。

### 5.5 当前限制与验收结论

- 参考已支持账号／受众分析与原笔记；后者沿用 8 份总上限，一篇算一份。超长参考明确要求减选，不截短原文。特定读者意见继续通过已有 `writingFocus` 入口，未把全部群聊自动加入。
- 重开恢复最后一次已发送的参考；尚未发送的选择变更（包括只选材料未输入消息、显式清空）也在当前标签页暂存。标题、正文和未发送要求按账号／选题隔离恢复；保存期间新增文字保留，已保存稿变更须手动选择恢复，不自动覆盖。标签页暂存不代替正式保存。分析预览是结果摘要，模型读取的是选中分析的完整允许结果；原笔记预览／输入均使用完整已保存正文，不包含图片理解。
- 等待显示真实状态与耗时，单次模型调用结束才展示回复和候选；没有调用中分段，也没有伪造“研究／审稿”进度。
- 当前段仅使用最近 12 条消息；候选正文仍继承 1,200 字符、总输出预算 1,800 tokens 的旧边界，长稿可能报长度错误。后续需独立写作长度契约，不以截短结果冒充完整稿件。
- Qwen-plus 构造稿检查共 3 次：前两次格式失败，诊断发现字符串引用和虚构场景；修正单助手提示后第 3 次格式通过、1 次请求约 4.25 秒，但“塞了十页幻灯片进去”“讲完才听说”仍有自然度和轻微改义问题。没有放宽解析器或添加样例故事，也不为测试强行再次改稿；下一轮需固定多样稿件核对表达质量。
- 界面与上下文隔离已通过组件／服务测试及桌面、390px、320px 浏览器检查；这些通过不等于四档案写作质量验收，也不代表已部署。

## 六、账号分析：恢复内容价值，重新组织报告

实施更新（2026-10-11）：六段常显、原标题／原句拆解、正文组织、完整依据保留和已知技术 ID 映射标题已实现。结构化 Qwen 账号报告默认采用 `staged` 增强流程：先整体认识，再并行精读代表作，最后用全部所选原文与有效观察形成报告；阶段摘要可见，局部无效内容不阻断其他可用结果。显式 `source_led` 仍可回退单次生成，旧文本与其他 provider 保持兼容。

当前账号模型默认为 `qwen3.8-max` 非思考。最近 QSheep／一粒鱼两份自动选篇报告均交付，但仍有概括范围过强、引用覆盖不全和把先后关系误解为直接关联的问题；这是已启用的产品默认，不是所有账号质量均已通过。下节保留改造前核对，逐轮样本、耗时与验证限制见[状态记录](status-and-todo.md)。

### 6.1 改造前核对：当时能确认的差异

新版并不只是模型“更差”，展示和内容需分别改。

| 维度 | 旧版优势／问题 | 当前版优势／问题 | 合并方向 |
| --- | --- | --- | --- |
| 可用写法 | 标题、开头、结构、对照和下一步比较直给；也可能过度概括成功原因 | 更重视认识账号，但旧拆解被“更多内容归纳”折叠 | 具体写法回到主报告，不恢复无依据的算法／因果断言 |
| 账号认识 | 定位和具体优势不足，容易只有话题和公式 | 有概要、关键词、优势、内容方向及读者价值；仍可能拼接不相关经历 | 多条内容线分别成立，再提炼真实共有的表达特点 |
| 证据与指标 | 模型填写的数字和高低表现原因容易误导 | 程序计算四项指标、来源引用和冻结快照更可靠 | 保留计算与来源，把模型注意力放回解释和创作建议 |
| 阅读体验 | 更直观，但字段卡和文字可能过多 | 字体和样式统一；主要发现被层层折叠，像一份缩水报告 | 主结论直接读，原文与技术详情再展开 |
| 作者声音 | `voiceFingerprint` 已生成 | 目前前端仍未展示 | 加入“你的表达方式”，用具体措辞和节奏解释，不贴人格标签 |

本轮核对的真实样本：

| 档案 | 较早真实记录 | 最新真实记录 |
| --- | --- | --- |
| QSheep | `dc0ae69f-636d-4a49-95e0-fce0c28cba9b`，9 月 21 日，20 篇 | `f7b7f956-aa65-4a54-a835-81e09cfb64c0`，10 月 9 日，10 篇 |
| 秀才加点冰 | `a7f4c6b7-c713-490e-9cdc-27746e0d509c`，9 月 23 日，4 篇 | `aea90602-32bc-4abb-8a65-9cf72b6e6d9e`，10 月 9 日，5 篇 |

QSheep 新关键词“人类学视角的 AI 使用者”引用的是课堂／人类学材料，引用本身不能支持 AI 融合判断。秀才旧报告用原文的“X，非 Y 也”拆解标题，新报告却更倾向泛化模板；新优势还出现用观影讨论结尾支撑“导游筛选三原则”的不相关引用。反过来，旧报告的“脱离主干即降权”“阻断搜索流量”等平台因果断言不值得恢复。

新旧样本和时间不同，正式记录也缺实际模型版本与过滤前结果，不能当同输入 A/B 证明整版模型退步；3 篇人工预写示例更不能作为模型优劣对照。后续应记录实际模型、提示版本和受控的原始结果诊断，避免只看到过滤后的空字段却无法定位原因；诊断不直接展示给作者，不记录凭据。

已确认一处提示样例污染：QSheep 新结果的 `stage_results_json.profile.profile.viralStructure.steps` 含“先核对费用，再决定是否报名”，整个冻结 `input_snapshot_json` 无该句；PROFILE 提示却恰好用这句示范引用格式。应删除这种可被当作账号内容的具体实例，改用不携带领域事实的结构说明；不能只追加一句“别抄示例”并认为已解决。

### 6.2 建议的主报告

按阅读顺序直接展示六段，不把它们默认全部折叠：

1. **这个账号给人的印象**：一段概要＋少量关键词。
2. **值得继续放大的优势**：每条说具体哪里好，带一篇可点开的例子。
3. **内容方向与读者价值**：允许并列垂类，不把所有笔记硬捏成一种身份。
4. **你的表达方式**：标题、开头、推进、措辞和节奏，挑最有特点的内容讲；展示现有风格指纹中的有效结果。
5. **哪些内容更有回应**：一到两组具体笔记比较，保留赞藏评分享的独立观察；没有可比材料就不强造对照。
6. **接下来值得试什么**：少量可执行尝试，说明借鉴哪篇的哪个做法；以发扬现有长处为先。

同一个发现只说一次，避免优势／表达习惯／鼓励反复换句话夸。积极不等于泛夸；简洁不等于藏掉观点。依据原文、完整指标明细与当次材料可以展开，主要结论、具体建议、关键动作必须直接可读。

移除“证据不足，需要保守判断”、核验条数、反复声明“不能代表”等公共结果中的固定话术；保留会改变操作的错误、缺数据、未保存、版本过期提示。预写示例与真实生成继续一处轻标记区分，不冒充。

### 6.3 输入、提示与验证

先修作者评论混入和不相关材料输入，再精简提示，最后检查渲染；不靠加更多禁令处理所有问题。

- 数字由程序提供；模型解释作品中具体发生的事，避免重复输出一套不受控数字。
- 输入明确区分完整正文、导语和已截取片段。秀才部分笔记只有短导语，不能按没有读到的全文结构评价其缺失。
- 不同时要求每条内容既填旧归纳又填新画像的同义描述；保留兼容字段，逐步确定一个主要内容结构。
- 对窄范围分析直说“这组笔记体现……”，不把局部样本包装成整个账号永久定位。页面只留简短范围标签。
- 四档案各挑固定样本，记录笔记 ID、范围、观察时间、模型、提示版本与实际请求数。先比较同一保存结果的新旧呈现，排除折叠影响；提示调整再做同输入、同模型的小规模对照。
- 对照审阅：是否更贴合账号、是否有具体好在哪里、是否有能照着尝试的写法、是否保留作者声音、是否引入未给事实、是否需要反复展开。人工预写示例作为目标参考，不作为模型成绩。
- 首次可先做 QSheep 多垂类／秀才同垂类两组，确认方向再扩到 Ag／一粒鱼；不重复大批量付费调用，不覆盖正式历史。
