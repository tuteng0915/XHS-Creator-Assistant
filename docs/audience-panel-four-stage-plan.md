# 受众 Panel 四阶段设计与实施计划

本文把 2026-10-04 用户确认的方向落实为后续开发计划：建立长期读者画像，针对本篇内容检索并组队，先独立试读再互相回应，最后由编辑助手给出可采用的修改反馈。目标是帮助创作者理解不同读法并改好当前作品，不把人物数量、讨论热闹程度或统一评分当成效果。

状态：四阶段主流程已确认；2026-10-04 完成设计稿，2026-10-05 已增量实现协议与快照底座、关闭讨论及定向问题的执行适配、公开准备页设置和历史任务摘要。结构化反馈已接后端校验、保存与卡片界面；单条局部提案的预览确认、采用、受限撤销及刷新恢复已接入创作画布，同组复测入口尚未实现。真实模型反馈效果仍需继续验证。本文是后续 Panel 改造的主计划；下方标为拟议的完整设计不因局部完成而视为全部上线，旧原型人工确认及多维大表单不重新启用。

## 当前实施进度

受限撤销已完成后端与画布接入：当前标题、正文和版本必须仍等于采用回执，用户在对照窗口再次确认后才能恢复修改前内容。原采用记录不改，独立保存 undoReceipt 与 undone 状态；恢复产生新版本。重复撤销返回原回执，不覆盖后续编辑；已撤销不能重做或改标拒绝。后续人工编辑、归档和其他提案改变版本时拒绝撤销，不进行多步回退。临时数据库迁移／事务／并发及页面窄屏／键盘检查通过；下一步进入固定同组复测。

画布现有“试读反馈改稿”入口，按当前账号和选题筛选完成的记录，展开后读取反馈及持久提案。选择单卡、明确插入或替换、编辑建议文字、保存并预览，再显式确认采用；可放弃或关闭后继续查看。历史页继续只读。未保存稿、AI 正在处理及保存中的画布不允许采用；确认请求期间继续输入的新文字保留，迟到结果不覆盖切换后的账号或选题。列表支持刷新／重新进入恢复；不自动发送模型请求。组件、全量测试及隔离浏览器的窄屏／键盘／刷新／采用交互已验证，不等同于正式账号端到端部署验收。

专用改稿提案的后端基础已完成：一条已核对的局部反馈对应一份持久 pending 提案，调用方明确选择替换原句、句前插入或句后插入，并提交具体文字；服务端保存前后对照，不默认把 suggestedText 当成替换正文。确认采用才写入 Topic，采用与回执同事务完成；旧版本、归档稿件、跨工作区、错误锚点拒绝写入。同一请求重复创建、同一提案重复采用返回原记录，不重复改稿。下一步为受限撤销与同组复测；没有模型定向改写或批量采用。

具体顾虑与多种改法展示已完成：界面核对当次来源中的原始顾虑后显示人物及内部记录标签；同顾虑、同原文位置、同优先级的卡片分组，完整保留每种表达和取舍，不执行语义去重或自动选择。无依据、旧字段缺失及不同位置独立显示，编辑可选创意不混入。组件全量及隔离浏览器窄屏／键盘检查通过；画布在复用这些反馈卡的基础上增加单卡准备修改入口，历史卡片不触发写入。

归因增量已实现：新汇总给出当次已记录的顾虑目录，reader 的修改卡需通过 readerConcernIds 关联 concerns／newConcerns，来源消息必须一致；keep 和编辑可选创意不需要顾虑，不做关键词猜测或自动降级。保存原文顾虑供详情回看，旧历史不回填。新构造混合样本的一次 qwen-plus 汇总中，两条修改都对应确实记录的版本选择疑问，认可角色得到保留卡，安静角色未被编造新问题。此样本的卡片归因通过；重复建议、插入与替换表达不清及旧自由文字风险提醒仍需处理。下一步先展示具体顾虑与同问题下的不同改法，再推进待确认提案契约，模型润色问题不应无限阻塞确认流程设计。

最新实测：统一 JSON 外层后，三张保留卡中两张通过，仍有一张误抄读者评论。因此新汇总改为选择程序提供的原文片段编号，程序展开为原有引文、出现序号、Unicode 坐标和内容指纹。目录只含冻结标题／正文，最多 64 项、每项最多 600 个码点，超限明确说明且可选全文建议；大纲只支持全文。编号绑定原文字段及版本，错编号、跨字段、过期和混填引文拒绝；旧引文格式仍可读。一次真实 qwen-plus 检查中三张卡的定位全部通过，但建议归因仍失败：读者未提出的隐忧被写成读者需求，概括省略原文限定条件。此改进只解决定位可靠性，不代表编辑建议或整条流程已验收；确认采用尚不开放。完整结果及下一轮归因任务见状态记录。

公开准备页现可选自然全文试读／定向试读、填写一到两个重点问题，并关闭互相回应。默认自然全文加讨论开启；没有正文仍按概念预演，不预测点击。改任务清除采用状态并保留手选名单，推荐回执按任务隔离，切回原任务只读恢复而不自动采用；切换账号／选题恢复默认任务。设置传入推荐及创建请求；界面错误不丢当前输入，旧协议回执不删除。已完成组件、公开页面传参及隔离窄屏／键盘检查，尚未做公开页面的真实模型端到端验收。

历史详情已在读者名单上方展示当次试读方式、重点问题及讨论设置，全部来自该运行快照；开启讨论不等于执行完成。旧记录缺字段明确未保存，未知版本或不完整任务不猜填。长问题、窄屏及切换历史已检查。

模拟结果及历史汇总现有只读反馈卡：先保留亮点，再展示关键调整，可选项默认折叠；展开后查看当次发言和原文高亮。上下文来自保存的运行或绑定该运行的实时事件，不取当前稿／人物库。缺失或不匹配来源明确提示，私有感受不冒充公开留言；切换运行清除展开状态。有效卡替代重复的旧内容调整列表，无卡仍保留旧总结并说明未取得卡片或未生成具体卡片。已做组件、窄屏和键盘检查，没有改稿动作。

显式 panelTask 的汇总现在请求 editorFeedback，并在写入前逐条校验来源、人物与冻结原文锚点。保留有效条目并记录无效原因，不让单条无效引用丢掉整份汇总，不重试模型；旧调用提示和保存字段保持原样。局部位置为 title/body、逐字 quote、从 1 开始的 occurrence，程序生成 Unicode code point 的零基 start／右开 end 和内容 SHA-256；重复匹配按起点逐字符搜索，可重叠。前端不可直接拿这些偏移调用 JavaScript 的 UTF-16 slice。全文建议用 whole 且无局部锚点，大纲暂不做细粒度定位。

来源附带程序判定的 public_comment、private_reading 或 public_reply，编辑额外建议必须 editor_optional、无读者来源且 priority=optional。反馈缺失、不合法、部分通过或全部通过分别保存诊断；validated 只代表字段与引用通过，不代表语义效果已验收。新汇总输出预算为 3,200 tokens，通常要求 1～3 条、最多 6 条，不增加调用次数。旧字符串建议仍兼容输出，卡片呈现无效计数且不把空数组说成“无需修改”；没有正文写入。

2026-10-05 用已保存的三位构造角色及同一篇练习稿做了一次 qwen-plus 汇总单阶段实测，反馈验收未通过：四条卡片放错 JSON 层级，没有卡片被采纳；还出现把读者评论当正文锚点、将已认可的内容写成待解决问题、正文定位配标题改写及无依据工具推荐。完整输出保留，不自动移位或重新调用掩盖失败。已把新协议提示改成唯一完整输出结构，并明确原文定位与发言依据、实际问题与编辑可选建议的区别；旧协议保持不变。修改后仅完成工程回归，下一轮先做一次有明确验收目标的同输入复测，再决定是否推进确认采用，不把本次 legacy 总结解析成功视为新反馈功能合格。

新推荐和模拟创建请求可显式携带 `panelTask`，含 `protocolVersion=panel/v1`、`readingMode=natural|guided`、`discussionEnabled`、`focusQuestions`。guided 需要一到两个非空问题，每条不超过 300 字；natural 不接收定向问题。未知字段、未知版本及非布尔讨论开关拒绝。该任务与原 demo/live `mode` 分开；未提交或为 null 的旧请求仍走旧分支，历史推荐指纹和幂等请求标识不加入隐式默认任务。

任务参与新推荐的模型输入、输入指纹和请求身份；创建模拟采用推荐时核对相同任务，不一致返回冲突并保留原记录。新协议要求选择已有模拟粉丝，不回退到临时生成人物。运行保存任务、现有完整人物快照、读者可见内容 SHA-256，以及 Topic 的基础更新时间；后续编辑不回写这些数据。这里保存版本是为后续改稿提供基础，不表示确认采用和版本比较已实现。旧记录不回填。

为避免接口接受设置却不执行，已同时接入最小运行适配：定向问题随冻结内容传入反应／回应／汇总，旧请求提示不变；关闭讨论确实跳过该轮调用，执行概况不把它算作缺失或沉默，实时事件与历史均说明未开启。当前 natural 是全文试读，不是标题点击测试；未新增布局，仅补历史状态解释与前端类型。完整 Panel 尚无真实 Qwen 效果验收。

2026-10-05 开始切片 2 的同池两题检验：用 QSheep 已保存的 5 位早期角色执行两次 qwen-plus 推荐，直接相关读者基本合理，但口语题的邻近人物出现申请材料等目的扩展，多个关注点写成稿件评审任务。已针对显式 panelTask 分开自然阅读动机与定向反馈的选人提示，强调可少选、不硬凑联系；旧请求提示不变。修改后仅通过工程回归，尚未再调用模型，不宣称效果已改善。诊断工具支持任务参数、输入哈希与独立语义待审标记，不把结构完成当作语义合格；详见状态记录及本地原始报告。

推荐请求幂等与既有运行恢复已做回归；这不等于普通模拟创建的重复 POST 已具备业务幂等键，本轮没有新增该能力。普通创建仍是新运行，复制旧人物快照的同组复测 API 也尚未开放。完整测试结果及下一步见[状态记录](status-and-todo.md)。

## 产品决定与实施边界

- 读者是账号资产，不为每个选题重新生成。受众分析仍优先生成 8 位、通常 6～8 位简短人物，全部有效角色自动保存；已编辑角色不被后续分析覆盖。
- 兴趣保持宽泛，需求和判断习惯具体。可以有同兴趣、不同诉求的多位人物，不靠只换语气制造差异，不强行设置支持者和反对者。
- Retrieval 指从当前账号已有读者中挑选，不是搜索互联网真人，也不是必须引入向量库。相关性与视角互补同时考虑，用户可以调整名单。
- Panel 是本次试读小组，不等于真实粉丝人口构成。默认三个槽位继续保留，可增加；不恢复三人上限，不自动把全部人物都拉来运行。
- 独立意见和互相回应都属于第三阶段。第四阶段由编辑助手承担；不要求所有读者都给专业写作建议。
- 模拟反馈先展示，由作者选择处理，再生成或采用改稿，不自动覆写当前正文。此决定适用于新的 Panel 反馈链路，不等于已经批准更改所有普通创作对话的自动应用方式。
- 延续文字输入、单左栏、蓝绿状态、简洁中文界面。不上图片理解、自动发布、通用 Agent 平台、跨账号共享或大规模用户社会模拟。

## 四阶段输入输出

### 第一阶段 建立可复用的读者画像

输入是所选账号笔记正文、读者评论和单独标明的作者背景回复。正文用于理解内容吸引什么需求；评论提供读法和诉求线索。作者答复不是读者需求，历史评论不是角色今后必须重复的话。

首版保留现有字段，不新增冗长人物问卷：

| 字段 | 职责 | 设计要求 |
| --- | --- | --- |
| `interests` | 通常愿意看的宽泛领域 | 跨选题复用，不写单篇标题或一次操作 |
| `coreConcern` | 想解决的问题或做出的决定 | 例如确定第一步及成本，不写空泛的追求成长 |
| `profile` | 条件式判断与行动 | 信息够用时怎样，缺少关键条件时怎样；不是永远追问同一件事 |
| `contentPreference` | 更容易理解和使用的形式 | 例如带对照的例子，不与兴趣混为一谈 |
| `expressionStyle` | 表达和参与习惯 | 可简短认可、追问、收藏或沉默，不预先指定本次行为 |
| `knowledgeContext` | 拟议的可选知识基础 | 只描述领域熟悉程度及术语理解；旧角色缺失时不猜填，先验证是否比现有 profile 更有用 |

例如同样关心效率工具，一人希望当天能试，步骤完整就行动；另一人先确认数据能否导出、是否绑定平台，再决定投入。两人都能喜欢同一篇，不必一个夸一个骂。这是我们自己的设计示例，不是从真实用户资料确认的身份。

实施先检查现有角色在哪些场景把“习惯”执行成“必做动作”。已经出现的“正文说无需报名仍索要报名入口”作为固定回归。优先改生成契约或新派生设定，不批量修补用户资产，不持续堆叠同义 few-shot；仅在样例确实改善留出题时保留。

验收：同一角色跨两类正文仍保持判断习惯，但行动随条件变化；同兴趣人物有实质不同诉求；不复制原评论、不杜撰固定生活频率；旧卡片可编辑且旧快照完全不变。

### 第二阶段 针对当前作品检索读者并组队

输入为读者可见标题和正文、当前账号定位、本账号 active 人物的当前编辑短卡，以及本次试读方式。作者希望重点服务的读者和问题属于编辑侧任务，不直接成为人物必须赞同的指令。

首版继续使用全池 LLM 选择，不先上 embedding 或二次模型重排。当前 64 KB 输入预算属于工程限制；超限保持明确提示和手选退路，不静默截掉池尾。等实际池规模、延迟和漏选案例证明需要时，再讨论粗筛加重排。

组队步骤：

1. 读懂本篇实际提供什么，区分概念与有正文的作品。
2. 对照已有需求和判断习惯找到相关候选，而不是只匹配兴趣词。
3. 在相关候选中选择能贡献不同读法的人；允许邻近读者，但不能为多样性硬塞无关角色。
4. 输出现有 `fitReason`、`contribution`、`relation`；拟增加一条组级 `compositionReason`，说明组合差异，不输出预定反应或虚构精确分数。
5. 用户确认或调整后冻结推荐名单与实际名单。少于目标人数或无匹配均可正常完成；不自动新建人物补足。

现有名字、来源及有效性快照继续使用。新增试读方式、重点问题若影响选人，必须进入推荐输入指纹和采用时校验；正文、画像或任务变化不能悄悄沿用旧推荐。推荐理由只给创作者看，不送进角色反应以诱导回答。

验收：同池不同题，推荐理由分别对应具体正文与人物需求；不要求名单必须反转。相同题更换候选排列不应单纯跟随列表前几位。零匹配、少量匹配、归档、重复、跨账号、过期、失败后手选都有回归。

### 第三阶段 先独立试读再选择互相回应

产品层建议两个阅读方式加一个讨论开关，而非三个互斥流程。这样“互相回应”仍属于第三阶段，可以接在任一种独立试读后。以下默认值为本计划建议，尚未上线：

- 自然阅读默认选中：先看标题形成是否继续看的选择，再按条件阅读正文；允许无感、跳过和不公开评论。
- 定向试读：明确邀请读者回答一到两个问题，例如哪里没看懂、哪个开头更吸引；这是被邀请反馈，不冒充自然留言。
- 互相回应默认开启：独立试读完成后，看见其他人的公开发言再回应。用户可关闭以缩短等待；没有可回应消息时正常跳过。

自然阅读的“先标题后正文”必须由程序控制可见输入，不能把全文先交给模型，再要求它假装还没读。为控制成本，分两步实现：先落地阅读方式与讨论开关，沿用全文试读并如实命名；随后再增加真正的标题预览子步骤，未实现前不得展示“预测点击”或称已测点开行为。只有标题时保持概念预演。

独立阶段的最小结果沿用 `understanding`、`triggerQuote`、`action`、`quote`，按需增加短的 `firstImpression`、`unresolvedQuestions`；字段取舍以是否支持反馈定位为准，不为每位人物生成长报告。内部理解和疑问只供作者及编辑助手查看，不自动成为评论区消息。不展示模型内部推理链。

回应阶段继续使用 `replyToId`、自己的第一反应和可见公开评论；新增 `responseKind` 可选枚举为认同、补充、提问、不同意。若变化了看法，保存变化点与简短原因，不覆盖第一轮。未在首轮评论的人可以回应；未返回首轮结果的人不能被编造前态。

首版只保留一轮互相回应，不新增自动无限辩论、强制共识或主持人逐人逼问。回应只看第一轮公开发言，不声称某人回应了并行阶段尚未生成的另一条回应。以后若需要串行追问，必须另做消息可见性与调用预算设计。

验收：独立调用不含其他人的答案；回应不能读取别人的内部疑问或不存在的消息；沉默与失败分开；一人失败保留其他人结果；关闭讨论没有讨论调用；讨论不能改写原始意见。全部人无公开评论时仍可基于内部试读结果生成编辑反馈，但不得伪称发生讨论。

### 第四阶段 把试读结果转成可选择的修改反馈

编辑助手读取冻结稿件、作者目标、人物快照、实际有效反应与回应、程序统计的完成情况。作者重点服务的读者只影响编辑取舍，不回头修改读者的原始反应。

已在显式 panelTask 的 synthesis 保留旧字段的基础上增加 `editorFeedback` 后端契约；页面优先读结构化结果、无有效卡片则使用旧字符串展示。每条反馈是一个具体编辑决定：

| 字段 | 内容及校验 |
| --- | --- |
| `id`、`kind` | 本次运行内唯一 ID；保留亮点、澄清、改写、补材料或可选探索 |
| `sourceType`、`sourceMessageIds` | 来自哪条个人反应或回应；编辑助手额外想到的建议单独标为 `editor_optional`，不假借读者名义 |
| `target` | 标题或正文位置、原文锚点、出现序号及内容指纹；全文建议可无局部锚点 |
| `observation`、`reason` | 已奏效的表达或具体疑问，以及对作者目标的影响 |
| `suggestedText` | 可选改写，不是每条都必须改；缺事实时列补充材料问题，不编造经历 |
| `beneficiaries`、`tradeoff` | 对哪些读者更有用，可能牺牲什么；允许保留作者原来的取舍 |
| `priority` | 编辑顺序，如优先处理、可选；不是用模拟票数算出来的流量收益 |

角色无公开评论但有有效内部试读记录时，反馈可以引用该记录，并显示“试读感受”，不能伪装成公开留言。引用有效只代表找得到原记录；还需人工确认建议确实回应了那个问题。

页面先展示“建议保留”，再给少量关键调整，其他放进展开区。点击卡片可看到对应人物发言和原文位置。作者可以暂不处理、直接采用可用改写，或勾选几条交给创作助手继续讨论；未选择的意见不自动变成改稿要求。

涉及写入时必须走专用待确认提案路径：冻结基础 Topic 版本 → 生成建议 → 显示前后对照 → 用户采用 → 同事务校验与更新 → 保存实际应用回执。版本过期拒绝覆盖；重复采用返回原回执。撤销只在当前稿仍等于该次应用版本时可用，之后有人工编辑则不能一键覆盖恢复。

锚点按冻结文本定位，不对当前稿做模糊字符串替换。重复句、中文 emoji 和换行要可精确核对；内部偏移统一采用明确的字符坐标约定，避免 Python 字符与浏览器 UTF-16 混用。优先使用段落编号、原句及出现序号定位，写入时再次校验原文和基础版本。

验收：每条必要修改有可回看的依据或明确标为编辑建议；亮点不丢；意见相互冲突时呈现取舍；已有完整说明不再机械要求补同一内容；拒绝或生成失败不改稿；采用不会新增未经确认的个人事实。

## 数据与执行契约

画像、推荐、模拟继续扩展现有资产与 JSON 快照，不创建独立 Panel 库。确认改稿阶段新增一张最小的 `panel_edit_proposals` 表：原通用提案要求关联聊天消息，无法直接承载已保存模拟反馈；专表避免制造聊天记录或修改不可变模拟历史。前后正文仍保存为 JSON 快照，不增加通用版本系统。以下为契约边界，尚未实现的部分继续按拟议方案推进：

| 对象 | 拟议增量 | 不变量 |
| --- | --- | --- |
| SimulatedFan | 可选知识基础及画像方法版本 | 原始分析与用户编辑分别保留，不自动迁移人格 |
| ReaderSelection | 试读任务快照、组级理由、选择规则版本 | 输入指纹覆盖实际模型输入；不修改候选人物 |
| SimulationRun 输入 | `panelProtocolVersion`、`readingMode`、`discussionEnabled`、重点问题、内容指纹、Topic 基础版本 | 现有 `mode` 继续表示 demo/live，不能混用；冻结实际人物版本与名单 |
| SimulationRun 结果 | 可选阅读轨迹、结构化编辑反馈 | 个人记录、回应和汇总分开；模型不能自行标记已采用 |
| 创作提案 | 运行及反馈 ID、基础正文、建议正文、状态、应用版本 | 原建议不可变；采用状态服务端维护，与 Topic 更新同事务 |
| 同组复测 | `parentSimulationId`、固定人物快照、两版内容标识 | 新运行不覆盖旧运行，比较时列出模式和模型等其他变化 |

### 改稿提案首版接口

撤销使用 `POST /api/workspaces/{workspaceId}/panel-edit-proposals/{proposalId}/undo`，请求为 `{"confirmed":true}`。仅 applied 可首次撤销；同事务校验 receipt.after、恢复 receipt.before 的标题正文并生成新更新时间，保存 undoReceipt.before／after／undoneAt，状态变为 undone。原 receipt 和 snapshot 保持不变。undone 的重复请求只读返回原回执，freshness 按撤销后的版本计算；不能再次 apply 或 reject。页面二次确认、未保存稿保护和历史状态已接入。它不是通用撤销栈，不能在后续编辑后强行恢复。

创建使用 `POST /api/workspaces/{workspaceId}/simulation-runs/{simulationId}/edit-proposals`，提交 `requestKey`、`feedbackId`、`expectedUpdatedAt`、`operation` 和 `text`。operation 必须为 `replace`、`insert_before` 或 `insert_after`；位置取该反馈经重新核对的冻结原文锚点，不接收自由坐标。生成只做确定性的文本拼接，不调用模型。响应包含 pending 状态、不可变 snapshot（反馈、修改前、建议稿、实际范围）、空 receipt 及当前版本是否仍适用的 freshness。

按运行恢复使用创建路径的 `GET`，只读返回该工作区／运行的提案，按创建时间倒序，含状态、快照、回执和 freshness；跨工作区返回 404。读取单条使用 `GET /api/workspaces/{workspaceId}/panel-edit-proposals/{proposalId}`；确认使用同路径的 `POST /apply` 且请求必须为 `{"confirmed":true}`；放弃使用 `POST /reject`。确认时再次核对标题、正文和更新时间，再原子更新 Topic 及 receipt.before／after／appliedAt。已采用记录重放只返回原回执，后续人工编辑不会被覆盖；已拒绝不能采用，已采用不能伪装成拒绝。相同 requestKey 内容不同返回 409，校验失败返回 422，跨工作区返回 404。

首版只处理已完成或部分完成的新版 Topic 试读，且当前稿必须仍等于试读时版本；标题和正文支持局部修改，重复句与 emoji 使用 Unicode 码点核对。keep、全文建议、手动概念及大纲不提供直接改稿；已改过稿需重新试读，不模糊迁移锚点。页面已接前后对照、采用、拒绝、受限撤销和持久提案恢复；对照为完整标题正文，尚无逐字符差异高亮。关闭前尚未保存的提案文字不持久化；已发出的请求不能通过关闭弹窗取消，过程中继续编辑会保留本地文字并提示核对版本。批量采用及同组复测仍待实施。

复测应复制旧运行的人物快照而非取当前编辑值，这与普通“从资产新建模拟”的校验路径不同，需要显式入口。同账号旧角色已归档时，可以明确“按当时人物复测”，不复活资产；原记录不存在或快照不完整时说明不能严格同组，不用现有角色补造。用户也可选择用最新人物重新测试，但两次不标为严格同组比较。

“固定同组”保持角色、阅读协议及问题不变，不意味着模型输出可确定复现。保存模型名、提示版本、输入指纹、调用数和失败阶段；模型或协议改变要标明不可直接归因于改稿。旧历史缺新字段按旧版展示，不猜填为自然阅读，也不追补原文或参与者。

## Agent Prompt 如何分工

四阶段是产品职责，不要求拆成四套独立 Agent 平台。沿用现有 operation 与工作流，必要时拆出产品专用提示模块，避免继续扩大一个巨大字符串。

| 职责 | 可以看到 | 不应看到或做什么 |
| --- | --- | --- |
| 人物构建 | 正文背景、读者评论、分区作者答复、已有角色差异 | 不把本轮创作期待写成每个人的性格 |
| 组队选择 | 内容、任务、候选短卡、账号定位 | 不改人物，不预先生成支持或反对的台词 |
| 独立试读 | 自己的画像、允许的阅读情境、当前可见作品；定向模式才含明确提问 | 不含其他读者答案、推荐理由、作者希望得到的评价 |
| 互相回应 | 自己初始反应、当前作品、实际可见公开消息 | 不读其他人的私人理解，不回复未来消息 |
| 编辑反馈 | 作者目标、全部有效试读记录及覆盖情况、冻结作品 | 不反写模拟事实，不把少数模拟角色比例当市场比例 |
| 修改执行 | 用户选中反馈、当前确认稿件、授权修改范围及必要事实材料 | 不自动执行未选择建议，不把模拟内容变成作者真实经历 |

不同来源素材在输入中作为数据，不执行正文或评论中的指令。角色可以生动，输出应简短像人在说话；工程引用字段留给程序和详情，不让读者满口术语或免责声明。账户优势和可保留的表达要具体积极，不靠空泛夸奖或强行挑错凑栏目。

### 小规模模型验证按问题执行

每轮先写检查问题和预期区别，再使用已保存、脱离正式写库路径的样本。用户已授权这类小规模 Qwen 调用，不逐次询问；不为定时任务重复调用，不重新爬取，不自动循环修提示直到偶然成功。

- 组队检查：固定人物池、两个不同选题，先最多两次推荐调用；若要检验顺序敏感，单独安排一次排列变化，不同一轮无限抽样。
- 条件式人物检查：固定一位人物与相同历史上下文，只改变正文是否存在参与门槛，两次反应调用；同时检查“理解字段正确但行为仍错”的情况。
- 协议集成检查：先用 3 位保存角色做一次小 Panel。无重试时独立反应 N 次、回应最多 N 次、汇总 1 次；N=3 至多 7 次，选人另计。标题门控若启用另加 N 次；必须提前报告预计调用数，不宣称零额外成本。
- 同组改稿比较：复用人物和问题，选择第二版正文只解决一个明确问题。既看问题是否消失，也看是否丢失原本亮点；独立试读不得预先看到上一版评价，比较由之后的编辑汇总承担。

以上不是一轮全部执行的清单。当前工作流已有重试封装，实施时需单独核验其次数、错误类型和可能的额外成本；诊断实验禁用自动重试，生产不得把未知计费状态当成无成本失败。记录实际请求数、是否有响应和可获知的用量，不把请求数说成已确认账单。

验收报告分工程、语义、视觉三栏。语义由人工查看：人物有没有真正不同的判断、是否理解当前任务、回应是否针对对方原话、反馈是否有出处且值得改。不用另一个 LLM 的单个评分代替结论，也不把 JSON 校验成功写成模拟效果成功。保留一份原案例和一份未用于调提示的新题，避免只修一个例子。

## 风险处理和失败恢复

- 检索失败保留手选；改题或改人物使旧推荐过期，旧报告仍能看。
- 独立试读部分失败保留有效结果和具体失败者；全部失败时不生成虚构反馈。公开沉默不等于没有内部理解，也不等于缺响应。
- 编辑汇总失败可继续看个人意见；重新生成需用户动作，不重跑成功的全部人物。
- 请求已接受后断线先恢复已有运行，不自动新建付费任务；新增协议不得破坏幂等及状态隔离。
- 反馈建议缺少可校验锚点可以展示为讨论建议，但不能直接替换正文；缺事实先由作者补充。
- 接受建议只表示本篇采用，不自动变成账号偏好、真实读者证据或新的成功案例。
