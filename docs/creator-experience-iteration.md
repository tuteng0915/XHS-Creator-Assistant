# 创作者体验第二轮改造

2026-09-25 更新：受众分析/模拟已按[研究方案](audience-simulation-research.md)进行首轮证据化调整。本文中的百分比合计 100% 和按估计比例 Top 3 的说明是上一轮实现记录，不再描述新运行；历史记录仍兼容保留。

本轮围绕一个账号完成浏览、诊断、选题创作和受众验证。保留内部工作台及既有 API，不迁移或删除历史生成结果。

## 执行顺序与验收

1. 收窄左栏，整理为四组父子入口：账号概览/我的笔记、账号诊断/分析历史、选题库/AI 创作助手、受众分析/受众模拟。添加账号只打开输入页，提交有效 URL 才创建档案；更新笔记沿用当前账号。测试空档案清理前备份数据库，非空档案不自动删除。
2. 概览展示可获得的粉丝、总获赞与已读取数量，未知指标不补造。概览和笔记页均可追加抓取；诊断完成留在诊断页，同时更新分析历史。
3. 增加独立受众分析记录，复用诊断的时间范围筛选，保存输入快照、分群、证据、估计比例和不确定性。真实模型分析内容及评论，不预设固定三种人；模拟使用该账号所选分析的 Top 3 分群，保存来源和角色快照。比例为模型估计，不代表平台真实人口统计。
4. 选题按置顶、最近编辑时间排序，新增正文。AI 创作助手左侧编辑标题/正文，右侧持久化多轮对话；复用现有后台对话任务。模型可提供更新，自动应用只能基于模型看到的编辑版本，冲突时保留建议而不覆盖人工修改。生成快照与用户编辑分开保存。
5. 增加接口与界面回归，覆盖导航、空档案、跨账号数据、分群校验、Top 3、置顶排序、对话重载和编辑冲突。更新文档、运行检查；真实抓取和付费模型验收单独进行，不由单元测试触发。

## 约束

页面文字保持克制。范围调整和临时填写使用弹窗。旧数据缺失粉丝等指标时显示未获取；不把评论样本组成包装成全量粉丝画像，不承诺真实曝光预测。账号数据始终隔离，模型不得更新其他账号的选题。

## 本轮实现

四组导航和 220px 左栏已实现；进入添加页不写数据库，提交链接后在同一事务创建账号和导入任务，相同链接重复提交复用已有任务，失败重试复用账号。已备份本地数据库并清理 6 个误创建的空“新账号档案”，保留包含历史资产的 `test` 档案。概览和笔记页提供抓取更多入口，诊断完成不自动跳到历史页。

MediaCrawler 当前版本不落盘创作者统计信息，新增独立适配器在原有抓取过程中保存公开昵称和聚合计数，不修改上游仓库。导入格式保留 `followers`、`totalLikes`、`likesAndCollections`；平台只给“获赞与收藏”时使用对应标签，绝不当作纯点赞。旧离线包仍兼容，无数据时显示未获取。

`audience_analyses` 保存独立分析的状态、范围、原始输入快照、模型输出和错误；创建请求启动后台任务，页面只轮询观察，刷新不会重启执行。同账号已有活动分析时复用任务；服务重启将已发出的中断调用标记失败，避免自动重复计费，等待中的任务继续执行。模型最多分析 100 条所选笔记、每条 50 条评论，截取限制在请求中说明；原始范围快照完整保留。分群比例需接近 100%，ID 必须唯一，最多 12 组。模拟冻结所选已完成受众分析的 Top 3 角色，历史模拟不随新分析变化；不足 3 组时使用实际组数。旧内部模拟 API 仍兼容未提供受众分析的调用。

Topic 增加正文和置顶字段，无新增版本表。公开选题库按置顶、更新时间排序。AI 创作助手左侧编辑标题与正文，右侧为可滚动对话，中间分隔线可拖动及键盘调整。每个 Topic 复用一条创作对话；后台复用现有持久化对话任务，模型使用真实配置。发送前保存本地编辑，回复更新使用乐观锁；如果人工编辑已改变版本，则保留 AI 建议而不覆盖。模型建议与输入上下文保存在对话消息中，Topic 保留当前可编辑内容及原有诊断生成快照。

## 人工验收边界

自动化测试不访问小红书，也不调用付费模型。仍需真人完成扫码、确认平台统计返回格式，并体验真实的受众分群质量和多轮创作手感。账号统计未获得时保持缺失，不用固定样例填充。远程网页扫码仍不属于本轮范围，浏览器登录窗口在运行抓取程序的机器上。
