# 2026-09-27 创作者链路验收

后续更新：本记录中的创作事实边界问题已增加提示词约束、待确认建议和更新引用校验，见 [当前状态](status-and-todo.md)。下文保留修复前的真实模型观察；本轮约束的真实 Qwen 效果尚未复验，不将历史验收结果视作新约束已生效的证据。

本轮用真实 Qwen 接口和公开版页面验证“账号诊断 → 选题 → AI 创作 → 受众分析 → 受众模拟”。这是一轮工程冒烟验收，不是受众模拟准确率实验。结论是：核心执行、持久化与账号隔离可以跑通，但模型内容质量仍有明确问题，不应将接口成功理解为分析可信。

## 环境与范围

测试使用独立临时 SQLite，从已有两个账号各取三条笔记；主测账号带十二条评论，另一账号带八条评论，仅用于检查切换隔离。未重新抓取小红书、未下载封面、未写入正式数据库。测试实例明确标为“验收”，不计入正式产品资产。

模型是阿里云端点的 `qwen-plus`，通过现有 Anthropic 兼容协议接入，并非调用 Anthropic 服务。共十四次模型操作：诊断三次、创作两次、受众分析两次、模拟七次。受众分析第一次因引用与输入不一致被拒绝，第二次通过；没有取消证据校验或用假响应替代失败。

## 页面与数据结果

| 检查 | 实际结果 |
| --- | --- |
| 账号诊断 | 三阶段完成，生成四个选题并自动保存，刷新后可从分析历史重开 |
| 历史选题到创作 | 发现来源丢失和旧版本问题；修复后保留原分析关联，首次保存成功 |
| 编辑后再次打开历史卡 | 复用同一个 Topic，保留修改后的标题和正文，不再创建副本 |
| AI 创作 | 两轮真实对话及正文落库，切换账号再返回可恢复；修复后无需刷新即可同步画布 |
| 受众分析 | 首次错误明确呈现；第二次保存四个阅读视角、已核验引文和代码组织的历史案例 |
| 受众模拟 | 使用已保存分析的前三个视角，三条独立反应、三条后续回应和总结全部保存，无阶段错误 |
| 模拟中刷新 | 后端继续执行，最终仅有一条 SimulationRun；历史可重开，不靠重连再次执行 |
| 账号隔离 | 另一个账号不显示主测账号的选题、分析或模拟；切回后原正文和对话仍在 |

刷新会回到账号概览，需要从侧栏重新打开相应历史，不代表恢复到刷新前的页面位置。本轮未覆盖真实扫码抓取、多设备、长时间断网或运行中进程崩溃；这些不能据本轮结果宣称通过。

## 本轮修复

历史结果渲染此前错误地引用当前执行记录，刷新后可能把生成选题保存成手动副本；现在显式传入选中的历史 AnalysisRun。选择选题会修改更新时间，卡片跳转现在使用选择接口返回的新版本，避免创作页首次保存发生版本冲突。服务端也按不可变生成快照识别原选题，允许用户改名后继续从旧分析卡找到它。

创作轮询此前先将对话标为结束，再异步读取正文，可能触发 effect 清理而丢弃正文更新；现在读完正文再完成轮询。模拟历史详情重新加载后，同步更新左侧列表状态，避免详情已完成而列表仍显示运行中。

修复前产生的测试副本保留在隔离库中供排查，没有自动清理正式用户的历史副本。本轮没有改变模型提示词、增加表或修改工作流图。

## 内容质量问题与下一步

优先处理事实边界。真实生成选题加入了未经素材证实的亲历场景和人物对话；首次创作即使要求不编造，仍把选题角度里的虚构意象带入正文。第二次逐字指定修改后能够纠正，但不应要求用户每次这样操作。建议明确区分原文事实、用户当前正文和生成建议，不能把旧分析或选题建议当成已发生的个人经历。创作请求还携带较大的账号背景，第二轮约 1.8 万输入 token；下一步应检查冲突上下文的优先级，而非机械删掉全局信息。

其次处理角色反应的同质化。本次三个读者的第一条“模拟评论”逐字重复了同一段正文；角色画像也出现大学生、应届生、女性等未充分证明的身份扩展。引文能通过字面核验，并不说明由引文推出的人物属性成立。建议强化阅读需求与身份推断的边界，明确“触发原文”和“读者新写的评论”的不同语义，并保留沉默选项。当前不新增标注集或效果对照实验，也不宣称 few-shot 已改善真实预测效果。

受众分析的首次失败没有保留模型原始输出，无法事后精确判断是 ID、引文字符还是来源对应错误；本轮只确认校验正常拒绝、有限重试通过，不将原因写成已定位。09-29 已为后续运行增加原始结构化输出留存、引用错误分类与分组级部分成功；不能据此反推本次历史失败的具体原因，也不等于真实模型质量问题已解决。
