## 2026-10-08 统一受众模拟入口

受众模拟独立于受众分析，作为一级导航。账号／已发布笔记／创作是同一页的三类对象，分别有历史，不是三个分散入口。顺序固定为选择类别与对象、可选推荐或手选、编辑本次角色、确认最终名单、进入同一个群聊与作者访谈；创作不以模拟为强制前置。

账号目标用 `accountProfileId` 指向当前工作区导入资料；最多 12 篇均匀文字样本，每篇 1200 字，范围显式保存。已有笔记继续用 `sourceMaterialId + noteId`；创作继续用既有 Topic／Draft／manual。新增 `simulationCategory` 与目标标题从冻结快照派生，旧 note 分类为已发布笔记，其他旧记录归创作，不需要回写历史。

`personaOverrides` 只允许最终选定粉丝的 `profile/coreConcern/expressionStyle`，冻结到当次人物；不写粉丝资产。推荐后的临时角色改动也算 `adjusted`，不是原样采用。三类读取方式共用推荐核验、独立反应、互相回应、作者追问；提示和最后结论按目标区分。

账号与已发布笔记的结论用 `synthesis.review`：summary、readerNeeds、keepDoing、nextTimeSuggestions，以及最多 5 条 topicIdeas。前者谈持续方向，后者谈下一篇同类型，不产出原文覆盖提案；创作仍用 editorFeedback。候选由作者单条加入选题库，以运行与候选 ID 幂等去重，不自动收录，不修改原笔记或既有编辑。旧版结论保留只读。分段展示足够，不需要逐字流式。

兴趣回答“这个人通常愿意看什么”，而不是复述某一篇笔记的标题、学校或一次操作。例如“留学、职业发展、个人成长”可以跨笔记复用，不宜写成“某校某专业某年申请材料”。需求回答“他这次希望得到什么帮助或做出什么决定”；性格则通过遇到某类内容后的判断和动作呈现，少用孤立的“理性、焦虑、外向”等标签。

| 字段 | 当前含义与约定 |
| --- | --- |
| `name` | 简短、便于选择的人物称呼，优先体现行为或判断方式。 |
| `interests` | 宽泛兴趣领域，生成目标 1～3 项；编辑与 API 最多 6 项，每项最多 30 字。旧结果缺失时为空，不从旧描述自动猜填。 |
| `profile` | 一句话说明行为触发及判断／行动，例如“看到成功故事先找相似起点，再决定要不要照做”。 |
| `coreConcern` | 具体想得到的帮助或决定，例如“确定自己这周先补哪项准备”。 |
| `contentPreference` | 希望看到的内容形式，例如“带时间和成本的步骤清单”，不再兼作兴趣或需求字段。 |
| `expressionStyle` | 说话和参与方式，例如“先收藏，缺少关键步骤才追问”。 |

每次仍以 8 位为优先、通常生成 6～8 位；材料少或部分引用未通过时允许更少，不为凑数制造身份背景。无法选定唯一需求或性格时，拆成几位合理的可能读者：他们可以喜欢同一领域，但需要不同帮助、在不同条件下被说服。允许相近意见、保持沉默或不感兴趣，不强制一正一反，也不将角色数量当成真实粉丝比例。宽兴趣不是阅读白名单，话题超出兴趣时仍可以因具体需求产生反应。

例如，同样对“留学、个人成长”感兴趣，一位读者可能“看到清单就想试，但没有时间和成本就先搁置”，需要“确定本周第一步”；另一位可能“先找与自己起点相似的案例，再决定是否投入”，需要“判断这条路径是否值得尝试”。两位都可以认可同一篇内容，只是提问和行动不同。若只把“快告诉我怎么做”改成“请问怎么做”，需求与判断都没变化，就不算有意义的角色差异。这些例子用于人工检查，不是硬编码到所有账号的两类粉丝。

分析短卡片展示兴趣、人物特点及主要需求，依据仍可展开；粉丝详情可以编辑这些字段并显式保存。模拟选择区也就地预览已保存的兴趣、需求和特点，展开可读完整描述、内容偏好及表达方式，切换角色重置展开状态，失效选择不展示旧画像。新的模拟冻结当时的编辑定义，独立反应与第二轮交流都读取同一角色字段。兴趣也随“添加不同声音”继承；旧客户端未提交兴趣时保留已有值，显式提交空列表才清空。原始分析、旧粉丝原始定义和历史运行不批量回写，不新增表或数据库迁移。

当前验收分两层：工程测试检查字段校验、旧数据兼容、保存／重开、快照冻结及两轮模型输入不漏字段；人工检查则把同一宽兴趣的角色并排阅读，确认需求能指向不同的帮助或决定，人物特点能解释不同动作，且不是把笔记标题换成受众名。用同一选题观察反应时，不要求制造争论，而要能看出每位为什么追问、认同、收藏或不参与。

粉丝列表内部切换已增加未保存保护：无改动直接进入另一位，有改动时提供继续编辑、放弃修改、保存并切换。保存和列表刷新完成后才切换，更新冲突或失败保留当前编辑；输入校验在确认弹窗中同样有效。更新已成功而刷新失败时保留已确认定义和版本，说明列表暂未刷新，重试只读列表、不再写入；后续新编辑不被刷新覆盖，归档同样处理。此保护不包括全局页面／账号切换或浏览器刷新。历史定义和模拟快照不因切换或保存编辑而改写。

派生不同声音也已分开处理创建与刷新：收到成功响应后保留全部返回角色，刷新失败不重新创建，关闭弹窗仍可“查看加入结果”。恢复成功后可以打开返回的第一位；若原角色有后续未保存编辑，则留在原角色。创建错误不会显示成原角色保存失败，重试只读、请求中防重复、窄屏与焦点返回均有回归。回执本身不跨页面刷新保存，已创建资产始终在数据库；未收到成功响应时仍依赖现有来源／模板幂等规则，不把网络不确定状态当成已经确认失败。

2026-10-02 已用 QSheep 的同批 10 条笔记、85 条评论进行了两次真实 Qwen 检查，据此补充了先归并上位兴趣、需求跨笔记复用的规则。作者解释、招募公告和提供帮助的回复不能被倒置为读者需求；询问指导也不意味着愿意付费。复测返回 8 位角色，宽兴趣和具体需求的区分更清楚，引用全部通过；仍有照抄评论语气和使用“高频收藏”等确定性行为表述的问题。导入评论目前缺作者身份标记，角色区分还不是确定性保证。2026-10-03 已用人工编写的三位角色和同一正文完成真实 Qwen 受控模拟，观察到参与差异，也发现角色虚构日程和汇总额外补写的问题；这不等于从真实账号推理出的角色已通过效果回测。上述验证未写正式资产，详见[检查记录](status-and-todo.md)。

## 按选题推荐读者：后端、Qwen 与主模拟页已接通

2026-10-04 历史页检查：姓名／推荐理由继续使用冻结快照，现有布局在 1100／375／320 像素可阅读长名称与长链接，缺姓名的旧记录不拿当前资产补造。新增读取请求序号与账号生命周期隔离，较早请求迟到不覆盖最后一次选择，跨账号往返不复活旧结果；响应归属不符拒绝显示，失败可重新点记录重读。随后完成模拟复盘保存隔离：旧回执不覆盖新选择，保存期间的新编辑保留，成功推进保存版本并提示剩余未保存内容；失败／冲突可人工重试，不自动合并。未新增模拟调用或改变推荐采纳／人物定义，未提供未提交备注跨页面恢复。

2026-10-03，产品讨论进一步提出“不同选题先挑对应读者”。这里的 retrieval 是从当前账号已有的模拟粉丝资产中选人，不是为每个话题重新生成一批人物，也不是从全局账号或互联网寻找真人。目前已落地输入／结果契约、SQLite 记录、后台执行、创建／查询接口、真实 Qwen provider，以及过期检查和模拟采用校验。应用使用 qwen／dashscope 且已配置 Qwen 密钥时自动接真实 provider；未配置时新建返回 503，不返回假推荐。主模拟页及公开快捷入口现已接入确认路径，历史页也已展示冻结的推荐／实际名单；它与后文尚未启用的“阅读需求原型匹配”是两件事。

当前基础实现：`services/reader_selection.py` 接收经过验证的本账号 FanResponse，排除 archived，完整保留 active 卡片的当前编辑字段和版本，不按 desiredCount 截断候选池。请求人数为正整数，默认 3 但没有三人上限；输入含账号、目标、人数及规则版本，生成确定性指纹。`services/audience_target.py` 提取原模拟读者可见内容，旧工作流方法保留为委托入口，返回内容相同且深复制，防止调用方修改嵌套数据时污染源快照。

结果使用 Pydantic 契约，只能返回已有 ID、短理由、视角贡献和 direct／adjacent 关联。空匹配需有说明；未知、归档、重复 ID 或试图增加姓名／性格字段的条目拒绝，其他合法项保留并标记部分完成。重复 ID 的全部重复条目都拒绝，不任意挑选其中一个理由；返回人数超过请求时整份报错，不静默截前三个。无效项全部被拒是 failed，不冒充有效无匹配；现有校验不判断理由是否语义贴合，也不保证人物差异。reader_selection operation 仅增加选人能力，不改现有反应／交流提示；推荐理由仍不进入模拟节点。

当前代码边界：`frontend/src/hooks/useSimulatedFans.ts` 初始取列表前三位 active 角色，后续尽量保留手选，它本身不负责按选题排序。公开 `CreatorSimulationSetup` 已改为先选题、预览正文，再推荐和确认人物；分析选题卡、选题库和创作助手都先进入这个确认页，不直接创建模拟。内部独立 Draft 仍保留旧兼容入口。后端 `SimulationRunService.create` 核验账号归属、角色唯一性和归档状态，并冻结当前编辑定义与版本；关联推荐时另行核验过期状态。历史页的 SimulationReaderSummary 只读本次快照，理由默认收起，不请求当前人物。

### 选人目标与输入

链路是“账号受众分析 → 保存读者池 → 确定本次选题或正文 → 推荐读者组合 → 用户可调整 → 保存快照并模拟”。账号受众分析仍优先生成 8 位、通常 6～8 位；默认推荐 3 位只是起点，不是上限，也不撤销现有增加槽位和手动选择。

推荐要兼顾关联与差异：宽泛兴趣解释他为什么可能注意到内容，具体需求解释他想得到什么帮助，人物特点解释他如何判断，表达习惯解释参与方式。可以推荐两位都关心职业发展、却分别先行动和先核算投入的人；不能只把同一句问题换成礼貌或尖锐口吻。允许合理的边缘读者、无明显关联或不足目标人数，不硬性分配支持／反对名额，不预先规定谁点赞、争论或沉默。此组合是一组阅读视角，不是实际触达人群或粉丝构成。

选人模型读取当前账号定位背景、读者可见的标题和正文，以及本账号所有 active 粉丝的简短卡片。卡片包括 `id`、`updatedAt`、`name`、`interests`、`profile`、`coreConcern`、`contentPreference`、`expressionStyle`，以当前可编辑值为准，不根据新选题覆盖人物。标题／正文沿用 `AudienceSimulationWorkflowService._simulation_target_context` 的读者可见内容规则；先提取共享纯函数再复用，不复制两套判定。仅标题时标为概念选人，不臆造正文。作者内部的 whyItFits、associatedPainPoint、营销策略、以前模拟反应和被推荐结果不进入本次选人输入；不需要重复携带完整历史评论来做检索。

首版无需向量数据库或关键词硬筛，完整短卡池进入；实际输入为定位、读者可见内容、人数和角色卡，内部账号 ID、版本戳留在快照而不占模型上下文。当前预算是 system＋user 文本 UTF-8 合计 64,000 bytes，属于产品调用尺寸限制，不冒充精确 token 数或模型窗口上限；超限记录 input_too_large 和尺寸，不截角色、不付费。输出额度 4,000 tokens，截断结果明确失败，不自动重试。空池直接保存有说明的无匹配，modelCalled=false。测试覆盖完整 8 位和请求 6 位；真实 5 位池两题各约 4.7 KB。大规模候选分批不在这一步实现。

### 记录与接口

推荐也属于生成结果，应有自己的最小 `ReaderSelection` 执行记录，不能只放在 React 状态或混入粉丝编辑字段。0033 迁移已新增 reader_selections 表及对应 repository／service，不新增版本表、目录或独立左栏大类；未来在模拟选择区恢复当前推荐，在模拟历史的“本次读者选择”中回看实际采用情况。

内部创建方法接收 prepare_reader_selection 构造的冻结输入。公开请求只接受目标、人数及 requestKey，禁止浏览器自行传人物池；0034 迁移增加 request_json，单独记录请求身份。相同账号／key／目标／人数优先返回原记录（包括失败），不因人物或正文已变化而重读；同 key 不同目标或人数返回冲突。首次请求在同一事务中读取当前账号定位、选题或草稿及所有 active 粉丝并冻结，角色编辑仅影响下一次新 key。事务内领取仅允许 pending → running，一个内部领取凭证对应一次结束操作，凭证不进入产品响应。结果按数据库中的快照验证，而不是调用者可变的领取副本；终态不可覆盖，部分有效项与校验警告一并保存，结构错误保存 invalid_output，不存原始 provider 异常文本。

ReaderSelectionWorker 已挂到应用 lifespan，构造或 GET 不执行。配置 provider 后先持有数据库旁的本地 OS 独占锁，才将旧 running 标为 interrupted，再串行扫描 pending；锁随进程退出释放，第二个工作者不能恢复第一个的运行。当前锁支持 macOS／Linux，无可用锁平台时不启动推荐工作者；它不是多机队列或高可用调度。应用关闭先取消推荐调用并保存 interrupted，再释放锁；调用设 120 秒超时，不自动重试。没有 provider 时不启扫描、不做恢复，新推荐返回 503，但历史读取和已存在请求重放仍可用。创建提交后响应丢失也不影响扫描，GET／关闭观察连接不控制任务。当前内部 pending 枚举不是跨账号公开 API。

| 字段 | 内容与约束 |
| --- | --- |
| `id`、`workspaceId`、`requestKey` | 当前账号内的执行身份；显式点击产生 requestKey，同一点击的网络重发复用，数据库唯一约束防重复任务。 |
| `status`、开始／结束时间、`error` | pending、running、completed、partially_completed、failed；无匹配是完成且列表为空，不算接口失败。 |
| `inputSnapshot`、`inputHash` | 冻结定位、读者可见目标、完整候选卡片及版本、目标人数；不冻结整个工作区。哈希含选人规则版本，用于识别变化，不冒充可重复推理保证。 |
| `proposedReaders` | 有序 `{fanId, fitReason, contribution, relation}`；理由与带来的视角各一小句，relation 为 direct／adjacent，仅描述关联，不是预测反应。 |
| `unmatchedReason`、`validationWarnings` | 无匹配或部分无效项的说明。陌生／跨账号 ID、重复 ID、空理由不进入推荐；不自动找另一位补位。 |
| `modelMetadata`、`selectorVersion` | 实际提供方、模型、可用用量及选择规则版本。输入、模型结果与时间作为执行历史不可编辑。 |

模型输出只允许选择输入池里的 ID，不返回新的姓名、性格或需求定义。每项最多一条短推荐理由和一条差异说明；服务端校验是身份、结构和长度检查，语义是否真相关仍需内容验收，不能靠分数或字符串不同证明人物多样性。部分条目无效时保留合法项并标记部分完成；空的合法推荐不自动升级为“重新生成受众”。

已新增两个端点：`POST /api/workspaces/{workspaceId}/reader-selections`，提交目标、desiredCount（默认 3）及 requestKey，返回 202 和原持久化记录；`GET /api/workspaces/{workspaceId}/reader-selections/{id}` 返回原记录并附加实时 freshness。查询显式带当前账号，不匹配时返回 404；这不是新增登录鉴权。目标沿用 topicId／draftId／manualTopic 三选一，未来公开页面仅使用前两种，不增加手填框。采用独立的轻量后台工作者和数据库领取，不重写现有模拟图；无需 SSE 或通用任务平台。

freshness 在一致的只读事务内重建输入，包含 status=current／stale／unavailable、reasons 和可用时的 currentInputHash。正文／标题、定位、完整读者池及人物版本变化分别返回 target_changed／positioning_changed／readers_changed；其他指纹差异为 inputs_changed。因为模型看过整个候选池，未采用人物被修改、新增或归档也会使推荐过期，不只检查被推荐者。选题置顶、内部 angle 和草稿内部 reuse 不属于读者输入，不因此过期。来源删除／无效为 source_unavailable；旧内部记录缺请求来源为 missing_source，不猜测有效。freshness 不是执行状态：current 的 pending 仍不能采用，stale 的 completed 仍保留原结果。GET 不写库、不重算模型，POST 重放不偷偷更新原快照。

同一 requestKey 不重复调用，返回现有记录；同 key 不同载荷返回冲突。刷新恢复只 GET 原记录，不自动重算。重启前仍 pending 的任务可安全继续；若在外部调用期间中断，标记 interrupted 失败并保留已落库结果，由下一次显式操作建立新记录，不承诺网络层“严格一次付费”，也不盲目重发未知结果的请求。新记录到达模型之前先冻结输入，模型返回后立即持久化。

创建模拟接口已新增可选 `readerSelectionId` 和 `readerSelectionInputHash`；采用时两者和最终 simulatedFanIds 必须齐全，后者仍是选择权威。只允许本账号 completed／partially_completed 且至少一位有效推荐的记录；无匹配、未完成、失败、指纹不符或目标实例不同均拒绝，不自动创建运行。同样正文的另一选题也不是同一来源。允许手动换成候选池内其他 active 人物，或增加超过推荐人数的角色；重复、未知、跨账号和归档校验沿用已有逻辑。

新 SimulationRun 的 inputSnapshot.readerSelection 保存原推荐 ID／指纹、proposedReaders、实际名单、校验警告和来源：最终有序名单与建议相同为 recommended，否则为 adjusted。仅手选已保存粉丝的新请求标 manual，不带推荐理由；旧兼容的自动派生人物请求不补假推荐来源，旧历史不回写。不需要新表或版本表，后续编辑粉丝不修改模拟中冻结的人物、建议和实际名单。

创建模拟时已在同一写事务内重新核验推荐、当前目标和整个候选池，再冻结最终人物与正文；不信任先前 GET 的 freshness。依据已变化返回 409，失败不创建运行、不入队。用户可重新推荐，或去掉推荐 ID／指纹按当前手选名单继续，不自动替换其选择。选人理由仅供创作者复盘，**不传给初始反应、交流或汇总模型充当行为依据**；这些节点的现有上下文白名单不变，测试确认初始图状态、实际注入反应及汇总调用均未带入理由。

### 页面与变更处理

公开模拟页已先展示选题及现有正文预览，再展示“推荐读者”和默认三个可增加的槽位。推荐区显示每位姓名和短理由，试读角度收进可展开项；返回后点“使用这组”才改变名单，不是每次进入页面就产生付费调用。自动首次填入未启用。

推荐过程中保留当前名单，用户可以继续手选或离开页面，后台任务不取消；返回时不覆盖期间的手动编辑。通过“使用这组”重新 GET 核验后一次性提交全部槽位，核验期间暂时禁用选题和槽位操作，避免等待期间覆盖新编辑。少于三位的合法推荐保留空槽，用户可补选；无匹配保留当前手动名单并简短说明。失败提供明确重试入口，不显示假推荐；“开始模拟”继续允许合法的手动选择。采用后修改名单仍携带原推荐关联，由服务端标识 adjusted；可明确点“仅按当前手选名单继续”解除关联。

切换账号立即清除该页面的候选展示，迟到响应不得填入新账号；切换选题或编辑正文后标记旧推荐不再对应当前内容，不自动清空手选人物。编辑／归档读者后也重新核对版本；归档者不可继续使用，普通编辑不自动变成新的推荐。重新进入页面按账号和目标恢复推荐 ID，GET 校验指纹；无记录时显示手动状态，不自动产生任务。已保存模拟始终按自己的快照打开，不随推荐或粉丝编辑变化。

请求回执按账号／选题保存在浏览器，只含 requestKey、人数及返回的 ID，不保存正文或密钥。创建前写回执，响应丢失后手动重试沿用 key 和人数；已有 ID 时刷新只 GET，不自动 POST。迟到响应只能更新原目标的回执，不能切入另一账号／选题的展示。当前未持久化未提交的槽位及“已采用”状态，刷新后推荐可重开，但需重新采用或手选。

分析选题卡、选题库和公开 AI 创作助手现在都先进入读者确认区，不在快捷入口直接创建运行。创作助手增加“选择模拟读者”，有修改则先保存当前标题／正文，失败保留本地编辑；等待保存时禁止编辑、重复提交和并行发送 AI 消息，切换选题／账号后不让旧保存回调跳转或覆盖新目标。AI 正在回复时暂时不可进入确认。保持同账号手选名单，允许不推荐直接模拟；推荐仍是显式选择，不因导航自动发起。

核对现有实现后明确：公开 AI 创作助手直接编辑 Topic 的正文，独立 Draft 属于隐藏的内部工作台。内部 Draft 与旧工作流模拟路径本轮未改，不新增公开草稿选择器；未来若开放该入口，再扩展确认目标及按类型隔离的回执。主模拟页及创作助手入口均已在隔离浏览器检查 320／375／1000 像素及键盘，无横向溢出；使用构造的 API 响应，不是正式服务端到端或模型效果验收。

### 验证与实施顺序

第一步仅实现候选输入包和输出契约的纯函数／服务单测，不接真实模型或前端：当前账号 active 角色完整进入，编辑值而非 original 生效；候选顺序不冒充相关性，跨账号／归档／重复／未知 ID 被拒；同一兴趣不同判断可并存，无匹配合法；目标读取与正式模拟一致。用保存的简短角色加两个不同选题构造假响应验证契约，不能将 fake 的推荐次序宣传成模型效果。

第二步已接通持久化记录、一次模型调用、POST／GET 和后台执行；过期与采用校验也已落地。第三步主模拟页和公开快捷入口已统一，测试覆盖迟到响应、手动采用与调整、过期、部分／失败／无匹配、刷新观察与请求重放，以及创作正文保存、换题和换账号。历史推荐／实际名单摘要也已完成：新运行在 proposedReaders 内额外冻结 name，实际名单使用 audiencePersonas／personaDefinitions。旧推荐缺姓名可从同次角色快照定位，无法定位就显示姓名未保存；旧来源不冒充手选，同名人物加序号，后续资产改名不影响历史。不回填旧记录，无需新表或重构模拟 LangGraph。

已用 QSheep 保存的 5 位早期读者及两篇人工编写测试正文做两次 qwen-plus 检查，共 3,093 tokens，未写正式资产。两题都选择工具实用、申请规划和经历共鸣三位，排序与理由变化，直接关联大体合理；名单相同可接受，但不能据此宣称组合多样性提高。部分解释拔高，“会追问”预写动作且添加套磁周期等未提供环节。随后提示改为每项建议 30～60 字、只写可观察的试读角度；这项提示调整未再真实复测。角色池是早期存量，不代表新版 8 人生成效果。后续分别检查“选了谁”与“读懂后怎么反应”，不把两者的改善混为一谈。

预期文件：后端新增 `services/reader_selection.py`、`repositories/reader_selections.py` 及一条迁移，扩展 models、api、workflow_worker 与 simulation_runs 的可选推荐关联；读者可见目标提取为共享纯函数。前端新增 `useReaderSelection` 与紧凑的推荐区域，扩展 useSimulatedFans 的原子采用操作，将 App 各模拟入口汇聚到确认区。每步均保持手动模拟可运行，先核对存量签名再落代码，不引入通用检索平台、向量库或新一层 agent 配置。

## 已有准备模块：阅读需求原型目录（未接入运行）

`backend/app/services/audience_prototypes.py` 内置 12 种可并列的阅读任务，如确认适用范围、拆解步骤、核对成本口径、核验依据和比较路径。每项只有稳定 ID、短名称、阅读任务和匹配问题；它不是用户、粉丝、人口分群，也不含阶层、MBTI、占比或默认表达风格。一个账号可以匹配多个，也可以一个都不匹配。目录目前只作为后续匹配的参考菜单，不进入受众分析 prompt、数据库、前端或模拟运行；历史结果和已有粉丝完全不受影响。

离线候选校验接受零至三个不重复的目录 ID，并要求每项提供匹配理由、不确定性及至少一条来自本次输入的逐字引用；反证引用如提供也要核验。输出只标为待确认提议，名称由本地目录提供，不接受额外的人格字段。这只是来源与结构校验，不能证明引文在语义上支持匹配。目前仍未接入模型、数据库、前端或模拟运行。

候选的 `citationBasis` 也由后端依据**支持性引用**计算：`note_only`、`comment_only` 或 `mixed`。反证引用不参与计算，模型不能自报这个字段。它只说明引文的来源组合：`comment_only` 并不表示评论者身份或匹配解释已经证实，`note_only` 也不能被显示成真实粉丝需求。

离线校验还拒绝同一候选内重复的逐字引文，以及把完全相同的引文同时放进支持和反证；同一笔记的不同片段仍可分别引用。这只消除明显的证据重复和自相矛盾，不判断引文是否在语义上支持阅读需求。

匹配输入包现在从本次分析快照确定性提取范围、已选笔记正文、对应评论、采样说明和固定原型目录，不携带作者资料、图片或工作区其他资产。候选引用直接对这份输入包核验；被截断、未发送的文字不能作为依据。这是后续模型调用的准备接口，当前不会自动调用模型或生成候选。

如果后续启用这条候选匹配路径，不能靠原型名称给当前账号贴标签：需针对本次选中的笔记正文与评论返回引用、来源类型、匹配理由与不匹配证据，最多做一次定向适配，再让用户确认后保存为模拟粉丝。未确认的原型及适配草稿不进入模拟快照。此确认规则仅属于尚未启用的候选路径；当前受众分析仍自动保存本轮全部有效简短角色。

## 现状与产品边界

当前受众分析从笔记和已采集评论归纳阅读视角，按原文校验引用；`SimulatedFan` 保存不可变的来源定义和可编辑的名称、兴趣领域、人物特点、关注点、内容偏好、表达习惯。运行时默认三个选择槽位，可以继续增加；所选定义冻结到 `SimulationRun` 输入快照，再做独立反应和条件性的评论区交流。QSheep 预存的五位是早期的五种需求视角，不在升级时重新生成人物；用户仍可从任一位派生不同声音。人物声音是明确的 demo 设定，不需要伪装成评论中已识别的人格。

`fan_voice_templates.py` 提供 12 种产品内置声音，包括行动、查证、共鸣、质疑、沉默、成本、风险、尝鲜、经验补充、反鸡汤、长线思考和玩梗围观。粉丝资产页的「添加不同声音」允许勾选多种并批量加入。同一来源粉丝和模板组合重复提交会复用原资产，不覆盖之后的编辑或归档；源粉丝、旧分析、旧模拟也不改写。新角色保留源分组的关注点与引用，在画像、内容偏好、表达习惯上加入不同设定，模拟节点实际读取这些字段。模板可单独增补或调整，不是用户自定义 Agent 平台；后续可用模型按账号素材再适配，但目前不是模型生成人物。

新设计保持“一个账号一套资产”的隔离关系。受众分析回答“材料中出现了哪些需求”，模拟粉丝回答“选取何种带有特征的阅读视角”，模拟运行回答“在这篇内容和这次情境下可能怎样反应”。三个对象不能互相覆盖：后续分析不改已有粉丝，粉丝编辑不改分析历史，模拟输出不回写为真实评论。

## 后续备选：多维字段与证据等级（未实现）

保留现有 `SimulatedFan` 表、`sourceAnalysisId`、`sourceGroupId`、`original`、`editable` 和时间戳。拟在 `editable` JSON 中增添可选的 `facets`，旧资产缺少它时继续按原字段运行；不增加独立的人格、版本或人口表。`profile` 仍作短摘要，`coreConcern`、`contentPreference`、`expressionStyle` 仍可编辑。新字段不能与这些文字各自悄悄形成两套互相矛盾的角色指令：编辑页要提示冲突；新模拟优先使用明确维度，旧模拟沿用现有摘要，旧运行快照完全不回写。

| 维度及字段 | 所属对象 | 默认与依据 |
| --- | --- | --- |
| `coreConcern` 主要需求、`contentPreference` 内容形式偏好 | 粉丝档案 | 沿用当前语义，不替代 `interests` 宽兴趣；从受众分析承接，可对应笔记和评论引用，视角允许重叠。 |
| `expressionStyle` 表达语气 | 粉丝档案 | 现有字段保留。没有同一评论者的多次表达时，只能标作模拟设定，不能声称识别了个人口吻。 |
| `facets.knowledgeContext` 对话题的了解程度 | 粉丝档案 | 可为“未知”；若评论明确说明自己的知识或经历，保留原文。 |
| `facets.decisionStyle` 判断时看重步骤、证据、共鸣等 | 粉丝档案 | 优先依据评论中的具体追问；一条评论不足以证明稳定性格。 |
| `facets.resourceConstraints` 预算、时间、信息渠道等约束 | 粉丝档案 | 默认未知。仅保留明确陈述或用户主动设定，不根据语气推断阶层。 |
| `facets.participationStyle` 是否倾向追问、质疑或保持沉默 | 粉丝档案 | 默认为假设；只有公开评论样本，无法测量沉默读者的比例。 |
| `mindset`、`immediateGoal`、`timePressure` | 本次模拟情境 | 默认未指定；可描述这次阅读时的心态与任务，不永久写进粉丝画像。 |

`editable.facets` 是固定键名到 `FacetValue` 的映射，不允许任意扩展字段。`FacetValue` 包含 `value: string | null`、`basis: direct_expression | interpretation | model_proposal | user_setting | unknown`、`evidenceRefs: AudienceEvidence[]` 和 `reason: string`。默认值是 `value=null`、`basis=unknown`、空引用。`direct_expression` 只表示被引评论直接表达了这项需求或约束；逐字引用通过检查，不等于模型对身份、性格或消费能力的推论也被证实。自动生成的建议先作为来源分析中的不可变候选结果保存，不进入 `editable.facets`，因此未确认建议不会驱动模拟；用户接受后仍标记 `model_proposal`，用户自行改写则标记 `user_setting`，两者都不得继承旧的“已核验”标记。空值是合法结果，不强行填满所有维度。

MBTI 不作为默认字段、自动推断结果或行为预测引擎。如果用户确实希望拿它做创作实验，可在“更多设定”添加自定义标签，并明确标为用户设定；社会经济处境优先记录可描述的资源约束，而不是凭评论给人贴阶层标签。当前模型对原文只做字面核验，新增结构必须进一步区分“引文存在”和“该引文支持此判断”。

## 后续备选：多维界面与交互（未实现）

左侧模拟粉丝列表继续按账号展示，不因新分析自动替换已有档案。列表卡片只呈现名称、主要需求、来源和启用状态，避免把全部维度铺满。点开一位粉丝后，右侧首先显示短摘要和 3 至 4 项最有用的维度；“查看依据”展开原文及笔记来源，“更多维度”才显示资源约束、参与倾向和自定义设定。每项在值旁展示“评论直接表达 / 解释性归纳 / AI 提议 / 人工设定 / 未知”，不再只给一整段 JSON。编辑必须显式保存，并延续现有的保存中、冲突和错误状态。

若启用额外维度，用户先预览原有需求与 AI 提议，再确认哪些维度进入可编辑档案；取消不应用新维度。候选建议保留在分析执行结果中，不靠未保存的弹窗状态维持。当前自动保存本轮全部有效角色的行为不因此改变，未确认的额外维度先留空；候选原型路径的独立确认要求见前文。既有预存粉丝照常可用，后续新分析不会覆盖它们的编辑或归档状态。

在受众模拟中，默认给三个选择槽位，各自从当前账号未归档粉丝中下拉选择；可新增更多槽位，不设三位上限，同一粉丝不能重复选择。后续可在槽位中打开简短画像预览。“本次心态”放在可选的“更多设置”里；不填写就不添加臆造的截止日期或情绪。创建运行时冻结所选档案的原始依据、当前编辑、各维度依据和本次情境。独立反应仍允许划走、读完不评论或发表评论；第二轮只看得到本轮公开评论，不让角色读取其他人的私下想法。结果页把历史原文、角色设定和模拟生成的话分开展示。

接口仍沿用现有资产路径：受众分析结果的每组可选带 `facetProposals`，但旧结果没有该字段也可保存；现有粉丝 `GET/PATCH` 接受可选的 `editable.facets`；创建模拟的请求可选带 `scenarioByFanId`，键只允许本次选中的粉丝 ID，值为 `mindset`、`immediateGoal`、`timePressure`。未提供这些字段时行为与今天一致。`SimulationRun.inputSnapshot` 保存最终采用的档案维度和情境，后续模型只读这份快照，而不是运行中重新查询可编辑资产。数据库继续使用现有 JSON 列，无需新增表或改写历史行。

## 后续备选的验证与实施门槛

先做不调用模型的工程验证：旧粉丝和历史模拟仍可读取；账号间不能互选；维度编辑不会覆盖原始定义；保存冲突和刷新恢复正确；待确认的模型提议不会进入模拟；没有引用的假设不会显示为“评论证实”；一旦生成运行，后改粉丝不改变旧快照。`direct_expression` 必须有至少一条属于来源分析快照的引用，`unknown` 必须为空值。来源 ID 与引文字面匹配应由确定性检查保证；“引文是否支持维度含义”需要单独审阅，不能由字符串包含关系代替。针对创作者经历误写成读者经历、评论未提及却补出阶层或 MBTI，加入明确的反例测试。

效果验证采用小规模、可复现的对照，而非把角色写得生动就视为成功。对同一篇留出笔记，分别比较不扮演角色的证据直接评审、现有扁平粉丝、多维粉丝；三者使用同一份历史证据和相近的调用预算，只改变画像组织方式。待测笔记的真实评论不得进入画像或提示词。记录问题命中、无依据身份断言、各角色答案重复、允许不评论的表现，以及费用和耗时。现有 `_tt`、QSheep 只够做案例级探索，不足以宣称真实粉丝预测准确率；若以后要证明发布效果，仍需新内容的前瞻反馈。不要把模拟角色的票数换算成曝光、点赞或评论量。

这部分仅是未来多维方案的实施建议，不阻塞当前简短角色的使用与迭代：可先把内置原型接入有证据的候选匹配，再增加可确认的额外维度，最后把维度和本次情境接入现有模拟节点。每一步都保留旧接口与运行历史，不需重写 LangGraph。当前只有原型目录、匹配输入包和离线候选校验；独立的 demo 人物声音扩充路径已接入 API、资产页和模拟提示词。两者尚未合并为模型匹配和一次定向适配流程。

## 文献依据与适用范围

在一项基于本人访谈和问卷的个人模拟研究中，丰富的自述资料优于只给人口属性；这不能直接迁移到我们缺少同一评论者历史的小红书样本。[Park 等的本人自述代理研究](https://arxiv.org/abs/2411.10109/)。另一项社交媒体评论模拟研究强调真实行为痕迹，并指出文风像真人与内容是否贴合可以分离。[Schwager 等的评论预测研究](https://aclanthology.org/2026.wassa-1.16/)。

一项测量研究不支持把 MBTI 指标解释为截然不同的二元人格类型，因此本设计不将其作为自动分型。[McCrae 与 Costa 的测量研究](https://doi.org/10.1111/j.1467-6494.1989.tb00759.x)。以人口属性提示角色也可能使生成结果受措辞和刻板印象影响。[Lutz 等的 persona prompt 实验](https://aclanthology.org/2025.findings-emnlp.1261/)。

合成人群在某些问卷中能接近均值，却可能压低差异并随提示词变化，因此本产品的模拟输出只用于发现可能的问题，不作人群比例或流量预测。[Bisbee 等的合成问卷对照](https://doi.org/10.1017/pan.2024.5)。现有研究与工程边界另见[受众方法文档](audience-simulation-methods.md)；这些研究结论不是 Qwen 或中文小红书效果的验收结果。
