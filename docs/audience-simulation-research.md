# 受众模拟：研究问题、证据边界与实验方案

日期：2026-09-25。本文保留最初研究问题与对照实验提案；下方“首轮落地”说明已实现边界。尚未运行真实模型对照实验，不能据此宣称模拟准确率提高。此前的安装文档修改与本研究独立。

机制层面的后续研究见 [受众发现、few-shot 与评论互动](audience-simulation-methods.md)：补充 Proxona 等直接相关工作，区分教学示例与行为案例，并定义条件性交流和分阶段消融；其中的候选机制尚未进入生产实现。

## 首轮落地（2026-09-25）

已将产品定位调整为发布前预演。新受众分析不再要求比例合计 100%，也不展示模型猜测的粉丝比例；改为需求视角和来源依据。每个视角必须带 noteId、可选 commentId、来源类型与逐字原文，后端在本次实际发给模型的截取输入中校验。评论直接表达与笔记内容推断分开显示。校验的是来源存在与原文匹配，不意味着模型对原文的解释已由真人验证。

新结果记录 `method=evidence_grounded_v1` 及实际采样数；前三个模拟视角按已引用的不同评论数、不同笔记数排序，仍只取最多三组。这是来源覆盖的简单排序，不是统计代表性或最终研究结论；更好的角色选择仍需对照实验。旧结果和旧百分比留在不可变历史中，前端不再画比例条，旧角色显示来源未核验。

模拟角色保留依据与局限；读者输入移除了选题的 whyItFits、associatedPainPoint、angle 等策略字段。结构/Brief 兼容入口也只提供白名单内的内容片段，而不提供目标读者和内部说服策略。缺少正文时标为概念预演，不假装评估了图像。没有已保存受众分析的旧兼容调用只生成假设性视角。

独立反应新增 comment/no_comment/skip，可以不公开评论；触发表达必须能在待测文本中找到。情境交流仍保留原有图节点，但只传公开模拟评论，不传其他人的私下顾虑和分析；不足两条公开评论时跳过，SSE 观察和历史页面均能恢复这一状态。总结明确不做粉丝人数、点赞或曝光预测。已有持久化、账号边界、部分失败和输入快照保留，不新增数据库表。

离线案例准备脚本为 `scripts/audience_research_cases.py`，不调用模型，不写业务数据库。从仓库根目录运行：

```bash
backend/.venv/bin/python scripts/audience_research_cases.py \
  /absolute/path/to/xhs_creator_profile.json \
  --target-id NOTE_ID \
  --output data/audience-research/case-001
```

输入文件使用 `xhs-creator-profile/v1` 格式，目标笔记必须有有效发布时间及唯一 noteId，并存在更早的历史笔记。新输出目录内，`inputs.json` 只包含目标文字与更早的历史材料；`heldout-answers.json` 单独保留目标实际评论，严禁送入待测模型。没有可靠时间的历史评论、未来评论、重复评论和与答案完全相同的评论会被排除，creator.profileText 等全局总结不进入输入。精确重复过滤不能发现所有语义泄漏，人工仍需审阅历史正文。输出目录必须不存在，防止覆盖既有研究记录。

这个脚本目前只完成评测准备，不是完整 A/B/C/E 实验执行器；匿名人工评审、费用上限和真实模型对照结果仍待下一步。以下“当前实现的研究性审计”是改动前的基线问题记录，不能当作改动后的未解决清单。

本轮验证：`cd backend && .venv/bin/python -m pytest -q -o addopts=''` 为 206 项通过（有既有 LangChain 弃用提示）；`npm --prefix frontend run test -- --run` 为 20 个文件、98 项通过（有本机 Node localstorage 参数警告）；`backend/.venv/bin/ruff check backend/app backend/tests scripts`、前端 `lint` / `build`、`git diff --check` 全部通过。脚本命令行测试验证中文内容、输入/答案分离与拒绝覆盖；注入模型响应的集成测试验证证据传递、暂停恢复、不评论、SSE 重放及部分失败。这些结果验证工程行为，不等于真实受众预测质量。

## 要回答什么问题

我们要验证的不是“LLM 能不能扮演几个用户”，而是：**给定一个账号在某个时间点之前的笔记与评论，以及一篇待发布内容，模拟能否比普通内容评审更好地发现真实读者会关心的问题，并帮助创作者做出更好的修改？**

这里有三个不同目标。第一是描述已经看到的评论：哪些需求反复出现，哪些表达存在争议。第二是预演新内容：哪些人可能感兴趣、误解或质疑，正文应该补什么。第三是预测真实效果：发出去会获得多少曝光、点赞和评论。前两个可以先做实验，第三个目前缺少足够的观测与校准数据，不能靠给 agent 加角色设定直接实现。

产品继续叫“受众模拟”，承诺收敛为“基于历史材料的发布前预演”。内部必须区分观察到的事实、模型解释和模拟情境。这一方向已获得本轮修改授权。

## 相关研究告诉了我们什么

研究并没有证明受众模拟无效，也没有证明“更多 agent 就更准确”。下面选取与本产品相关的原始论文和项目来源；调查问卷、美国受访者和 Reddit/X 的结果不能直接当作中文小红书场景的准确率。

| 研究 | 与本项目相关的结果 | 对我们的启发与限制 |
| --- | --- | --- |
| [Whose Opinions Do Language Models Reflect?，ICML 2023](https://proceedings.mlr.press/v202/santurkar23a.html) | 用 OpinionQA 比较模型与不同美国人口群体的观点；明确指示扮演某个群体后，仍然存在分布偏差。 | “留学生”“家长”等标签不能保证观点代表性。它研究的是问卷观点，不是小红书评论预测。 |
| [LLM Agents Grounded in Self-Reports Enable General-Purpose Simulation of Individuals，arXiv v3，2026](https://arxiv.org/abs/2411.10109v3) | 基于 1,052 名受访者的访谈、问卷或组合信息，实测与真人回答的一致性；丰富的本人资料优于仅有人口标签的条件。 | 值得借鉴的是证据条件与留出验证，不是照搬论文准确率。这里使用了系统性自述资料，我们只有少量公开评论，两者信息量差别很大。该论文早期标题为 Generative Agent Simulations of 1,000 People。 |
| [Benchmarking Distributional Alignment of Large Language Models，NAACL 2025](https://aclanthology.org/2025.naacl-long.2/) | 比较题目领域、引导方式和分布表达方式，发现直接描述观点分布可以优于靠反复生成回答来模拟分布；不同格式影响表现。 | 必须加入“单次直接分析”对照，不能默认多角色抽样更科学。论文主要采用闭合式问卷，开放评论仍需自己的评价方法。 |
| [OASIS，固定论文版本 v4](https://arxiv.org/html/2411.11581v4) 与 [官方代码](https://github.com/camel-ai/oasis) | 将推荐、互动和时间放进社交模拟环境；论文也明确指出推荐系统简化、用户抽象与真实传播的差距。 | 可借鉴“用户看到了什么再做什么”的环境设计。规模化框架不等于小红书传播预测器，本项目暂不需要接入百万 agent 平台。 |

综合这些证据，我的判断是：最值得投入的方向是**有依据的受众差异、明确的读者可见信息、可复现的对照实验**。角色故事是否生动、评论看起来像不像真人，只能评价表达效果，不能单独证明预测有效。

## 当前实现的研究性审计

当前主路径是“受众分析 → 取前三组 → 独立第一反应 → 看其他人的反应后再次回应 → 策略总结”。持久化、输入快照、账号边界和部分失败保留已经具备，适合复用。问题主要在模拟的测量目标与上下文，不需要先重写 LangGraph。

| 已查到的行为 | 为什么影响研究可信度 | 建议实验或调整方向 |
| --- | --- | --- |
| `AudienceResult` 要求各组 `estimatedPercent` 合计约为 100%；prompt 说明是主观估计。 | 没有实际分类计数和抽样分母，却呈现完整分布；几种诉求也可能属于同一个人，不互斥。 | 将评论主题的可计算占比与受众假设分开；允许无法判断，不强求所有受众组成百分比。 |
| 受众分析最多输入 100 条笔记，每条取前 50 条评论；只传评论文本。 | 丢失已有 commentId、时间及采样顺序语义；前若干条不等于随机样本，无法代表所有读者。 | 保留笔记/评论引用及采集说明，报告覆盖范围，不把热门评论或高频发言当作人数。 |
| 范围筛选基于笔记发布时间，不按评论产生时间裁剪。 | “某段时间内发布的笔记的受众”不同于“某段时间内发表的评论的受众”；历史回测尤其可能混入未来评论。 | 明确两个时间定义；回测单独按 comment.createTime 截断，缺失时间时说明不能做严格时序验证。 |
| 受众结果的前三组进入运行快照，但 `PersonaDefinition` 没有 evidence 和 estimatedPercent 字段，校验后不再传给后续节点。 | 角色只剩概括性文字；最终模拟并没有使用保存的证据链，也不是按这些比例加权。 | 传递经过核验的 evidenceRefs、证据摘要和局限；不能声称当前结果是“按粉丝比例模拟”。 |
| 模拟对象包含 `whyItFits`、`associatedPainPoint`、`angle` 等创作侧信息。 | 真人读者通常看不到“为什么这个选题适合他”；让角色提前知道策略判断，可能诱导它认同创作者。 | 拆成读者可见内容与仅供分析器使用的策略背景，做去除策略字段的消融。 |
| 每个角色必须给出一次反应，然后再对其他人回应。 | 没有划走、不评论、不读评论等行为；第二轮强制所有人看到他人意见，容易把评论区写成讨论会。 | 先独立预演；允许无公开评论；第二轮只作为“如果看到这些评论”的可选情境。 |
| 永远取主观比例 Top 3，每组一个角色。 | 组内差异和少数但重要的异议可能被遗漏；三句评论不是三次独立真人观测。 | 比较固定 Top 3 与证据覆盖选择，不默认增加人数；关键异议单列，不假装它是高频群体。 |
| 当前总结是定性策略判断，没有经过校准的曝光/点赞预测模型。 | 结构化 JSON 正确、工作流成功，不等于结果能预测传播。 | 保留定性价值，先建立历史基线与前瞻验证，再讨论数值预测。 |

## 一个适合我们产品的候选方法

### 先建立可追溯的受众依据

从所选笔记的评论中提取诉求、问题、反对理由和表达习惯，并引用 noteId/commentId。把“评论明确表达”“由内容间接推断”“为覆盖盲点而提出的假设”分开。分类以需求与阅读情境为主，例如“准备申请、急需操作步骤的人”，而不是凭一句话编造年龄、收入和完整人生经历。一个人可以有多个需求，因此这些首先是视角，不必声称是互斥人口分群。

有足够样本时，可以展示“已采集评论中，有多少条提到某问题”，分母由代码计算，标明去重、无关评论、作者回复及多标签规则。评论者身份不充分时，不能把评论条数换成人数；也不能推断未评论的沉默读者占比。少量或没有评论时，允许输出较少视角，并明确它们主要是内容推断。

完整历史仍可供受众研究阶段参考；但具体角色只看与其有关的证据。这不是保守地限制全局信息，而是区分研究者拥有的材料与被模拟读者能看到的材料。

### 再模拟一个真实的阅读任务

角色接收自己的需求、相关历史表达，以及待发布的标题和正文；只有已提供且实际处理过的封面才能进入视觉判断。没有封面时不能推断其吸引力。尚无正文时应明确为“选题概念预演”，不是完整作品测试。

读者输出应区分理解、感受与公开行动：它认为文章在说什么，哪句引起兴趣或疑惑，是否有想追问的事；如果不想评论，评论字段可以为空。用问题位置和引用片段支撑修改建议，避免人人都像专业内容顾问。允许模拟划走或收藏等情境，但在没有真实行为数据校准前，不把这些模拟动作频率展示为用户概率。

群体交流暂不作为默认可信度来源。实验中可保留第二轮，但要说明读者具体看到了哪些评论，允许不回应，并与独立反应分开保存。独立反应回答“看到内容会怎么想”，第二轮回答“看到这些意见后可能怎么想”，不是同一项观测。

### 最后回到创作决策

产品结果优先回答三件事：可能打动谁，最值得修正的误解或疑虑是什么，以及具体该改哪一段。每项主要结论能展开查看历史依据、模拟例句与未知信息。模拟评论清楚标为生成内容，不混进原始评论资产，也不能在下一轮被当成真实受众证据重新训练自己的结论。

若比较 A/B 两版，固定同一份受众依据，使用新会话分别模拟并打乱呈现顺序，不向读者泄露哪版是“改进版”。独立反应之后再汇总差异。这样可以研究修改是否解决了某个疑问；但未经线上实验，不能把模拟偏好差异说成真实增益或因果效果。

候选输出的最小结构为：`evidenceSnapshot`（范围、引用、采样与局限）、`readerViews`（需求与依据）、`stimulusSnapshot`（本次实际可见内容）、`reactions`（理解、疑问、可空评论及触发片段）、`findings`（结论、修改位置、证据与分歧）。这是实验数据约定，不要求现在增加产品表或新的通用 agent 框架。

## 如何验证，而不是只看演示效果

### 对照组与研究假设

| 条件 | 内容 | 回答的问题 |
| --- | --- | --- |
| A：普通评审 | 单次模型读取待发布内容，不给历史受众资料 | 通用模型常识已经能做到多少？ |
| B：证据直接评审 | 单次模型读取相同内容和历史评论证据，不扮演角色 | 历史证据本身增加了什么？ |
| C：证据读者预演 | 与 B 同一份证据，多个视角独立反应，再总结 | 角色分解是否优于同样信息下的直接分析？ |
| D：增加交流 | C 的基础上增加条件性的第二轮互动 | 交流能否发现额外问题，还是制造更多噪声？ |
| E：改动前实现 | 固定首轮证据化改动前的 Top 3 + 两轮回应 prompt、schema 与代码版本，不跟随当前主分支变化 | 新方案相较旧体验是否值得替换？ |

核心假设是 B 优于 A，C 在某些任务上优于 B；D 是否优于 C 不做先验承诺。先测试 A/B/C/E，只有独立模拟显示价值后再测试 D。B/C 同时控制证据量，并补充相近 token 预算的对照，避免把多花几倍调用费用误认为角色方法有效。所有条件固定模型、参数、材料和输出长度约束，记录 prompt 哈希、可获得的模型版本、调用时间、token 和延迟。

### 数据与防泄漏

先用已有 `_tt`、QSheep 数据做小规模探索，核对实际可用的笔记、评论与时间字段，不把先前记录的样本数量当作最新统计。这两份样本适合跑通研究流程，不足以证明跨账号效果。

每个测试单位是一篇被留出的真实笔记，而不是一条模型生成评论。模拟可以看到这篇笔记的内容，但不能看到它的真实评论、互动结果、分析总结，或由其评论派生出来的痛点。历史受众资料只使用时间截点以前的信息。已有账号摘要可能包含所有笔记的总结，必须在切分后重建；不能先全量分析再把某篇正文从列表里删掉。

评论时间完整时做滚动时间切分；时间缺失时可以做留一笔记的离线探索，但要称为关联性重建测试，不能宣称预测未来。重复文本、跨帖相同评论及来自目标帖的引用需要去重与检查。历史帖子可能进入模型预训练，因此回溯结果还需要后续新发布内容的前瞻验证。

### 评价指标

首要指标是**实际问题命中与错误警报的平衡**：模型指出的问题是否出现在留出评论中，同时惩罚编造大量可能性来提高命中率。将双方归一到独立的问题/诉求单元，用人工核对的 precision/recall 或同等可解释的计数呈现。观察不到的评论也可能存在，因此不能把“本次样本没出现”一律断言为现实中不存在；需要标注未知与采样局限。

第二项是证据正确性：历史引文是否真实存在、ID 是否正确、有没有把内容推断写成评论事实，以及是否泄露测试答案。第三项是创作效用：匿名打乱条件后，请创作者评价建议是否具体、是否指出此前没注意到的问题、是否愿意采用。最好由两位独立评审标一部分样本并记录分歧；LLM judge 可辅助整理，不作为唯一裁判，更不能让生成者自己打分作为主要证据。

同时记录重复运行的结论波动、无依据判断、失败率、费用和等待时间。可以从少量案例、每条件三次运行开始检查敏感性，但三次只是工程探索参数，不构成统计效力保证。重复生成不是新增真人样本；比较时以笔记/账号为单位报告差异，不能把几百条模拟评论当作几百位受访者。样本扩大前，只能报告案例级结果及局限。

有明确互斥标签和足够真实标注时才比较标签分布；多标签诉求不能硬凑一个和为 100% 的人口分布。角色自报的信心分数不等于经过校准的置信度。

### 为什么暂不预测点赞量

公开抓取通常能拿到互动计数，却缺少曝光分母、推荐分发过程以及同一发布后时长的观测。老帖有更长累积时间，内容题材与传播机会也不同。仅从几条历史笔记和模拟发言，无法可靠区分内容接受度与分发效果。

近期可以给出过去相似笔记的实际表现作为参照，但注明采集时间和相似条件，不称为预测区间。未来若用户能提供发布后固定窗口的数据与曝光，再单独比较简单历史基线、统计预测和模拟增量；绝不能把三个人设的支持票数线性换算成点赞数。A/B 的模拟相对偏好也需要验证，不能因为不报绝对数就默认可靠。

## 落地顺序与决策门槛

第一步做离线研究夹具：版本化案例清单、输入/答案物理分离、时间与来源检查、匿名评审表、测试脚本。这里不需要模型调用、更多抓取或修改公开 UI。单元测试能验证切分、引用、账号隔离和缺失数据处理，不能证明模拟代表真实人群。

第二步用少量真实 Qwen 调用运行 A/B/C/E，费用上限在执行前确认，输出原始结果、条件对照、失败记录和成本表。不给模型看真实答案，也不把测试产物写成用户正式资产。当前尚未执行这一实验，因此没有“新方法优于旧方法”的结论。

第三步才选择实现。若 B 与 C 相当，优先采用更便宜的证据直接评审，角色例句可作为解释层；若 C 在问题发现或修改帮助上稳定改善且错误警报不增加，才升级角色链路。D 没有增益则不作为默认步骤。证据引用和账号边界必须通过确定性检查；效果验收在看实验结果前约定，不事后挑最好看的案例。

第四步做前瞻验证：用户发布新内容前冻结预演结果，发布后在约定窗口收集真实反馈，再比较预演命中与盲点。无需为了评估诱导用户发布争议内容或批量抓取。若想验证“按建议修改是否提升效果”，还需另行设计真人评审或平台允许的实验，普通前后对比不能当作因果证明。

需要产品方决策：是否同意现阶段以“发布前预演和修改建议”为主、暂不承诺流量预测；是否愿意让施琦姗或创作者对匿名结果做少量人工评审。具体采用几个人设、几轮对话、是否换框架，不应先靠偏好拍板，而应由上述实验决定。
