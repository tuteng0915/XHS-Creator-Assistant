# 档案内的 Oracle 预写示例

## 本轮打磨标准

此次只精修四份已有示例，不扩案例数。画像先说清这个账号值得被记住的具体特点；候选体现不同的判断与行动，群聊先表达读者自己的收获或困惑，再回应同伴，避免全员充当编辑。允许喜欢原文、意见保留和自然短回应，不要求讨论最后达成一致。

页面优先展示内容：辅助设置按需展开，原笔记就地可读；来源说明保留一处，纯人数摘要不重复。正式模型生成路径不改。验收包括四账号内容对照、引用不变、窄屏与键盘阅读、保存操作回归，以及更新前后旧数据完整性核对。润色原位应用到同一批示例 ID；备份并核对旧行指纹后才能写入，有人工编辑或下游采用时停止，不静默覆盖。

## 打开方式

示例直接放在现有 QSheep、秀才加点冰、Ag、一粒鱼四个档案中，不另建账号、案例总览或独立演示页面。选中账号后，沿用正常入口：

1. **分析历史**：打开带“预写示例”标记的账号认识，查看概要、关键词、优势及对应笔记依据。
2. **受众分析**：打开该账号的预写历史，比较 6 位简短候选；喜欢哪位，再手动收录。
3. **受众模拟 → 已发布笔记级**：打开预写模拟历史，查看 3 位读者的个人意见、互相回应、作者追问及下一篇建议。

讨论前可以展开“查看本次笔记”对照原文；“本次读者与设置”收纳固定名单和复盘备注。未保存的复盘会继续提示。账号历史中的“本次分析的材料”也能查看当时完整文字，不必在不同页面之间来回寻找。

页面使用正常前后端读取已保存记录，查看示例不调用模型。它不是只启动前端即可运行的独立离线网页；正常新建分析、推荐和模拟仍走 Qwen。

## 哪些是真的，哪些是预写的

- **真实材料**：对应账号本地已保存的笔记标题和正文。每份画像使用 3 篇材料，讨论只围绕其中一篇；范围及原文冻结在记录里。
- **人工编排**：账号认识、模拟人物、发言、作者问答和选题建议。它们是理想展示内容，不是一次真实模型调用，也不是实际粉丝调查或流量归因。
- **保留作者决定**：安装时不收录粉丝、不创建选题、不改写笔记。作者主动点“收录”或“加入选题库”才按原有流程保存正式资产。
- **不伪造动态结果**：群聊展示固定的参与名单和预写问答，不冒充执行过读者推荐；不提供可触发模型的自由追问。需要新分析时使用原有正常入口。

所有新历史使用 `origin=oracle_showcase`；列表和详情显示“预写示例”，详情另有一句来源说明。不会把它们混记为 Qwen 生成结果。旧历史、已编辑读者和作品不变。

## 在已有数据库中安装

先按[数据交接说明](data-handoff.md)放好包含这四份档案的数据库，再在仓库根目录运行：

```bash
# 只读检查：确认账号身份、所需笔记与逐字引文均匹配
backend/.venv/bin/python scripts/seed_workspace_showcases.py

# 先备份数据库，再一次性追加记录
backend/.venv/bin/python scripts/seed_workspace_showcases.py --apply
```

其他数据库可加 `--database /absolute/path/to/app.sqlite3`。脚本不会新建数据库、迁移表、创建账号、抓取或调用模型。应用前使用 SQLite 在线备份，备份位于忽略提交的 `data/backups/`，仅当前用户可读写。全部材料校验通过后才在一个事务中追加。

相同版本重复执行不重复写入；已有记录不覆盖。缺失账号、材料、引文不匹配、档案归属冲突或不完整的旧示例集均停止，不拿其他档案凑数。

已安装的示例若需润色，普通安装命令仍然跳过，不会自动刷新。维护时使用 `workspace_showcase_refresh.py` 的只读计划与显式应用函数：先备份，再比对旧行／材料／引用指纹，只更新允许的文案字段。示例已被收录、采用或写过复盘时拒绝原位更新；不能借“润色”改变原文、指标、引用、参与身份或覆盖人工资产。本机本轮原位更新了 4 份画像与 4 场讨论，记录总数保持 12。

## 维护与验收

人工内容位于 `backend/app/services/workspace_showcase_content.py`；导入与核验位于 `workspace_showcases.py`。只在仓库保存必要的笔记 ID 和短摘，不复制整份档案或密钥。完整冻结材料只进入本地数据库。

验收分开看：材料与归属正确、人物与讨论贴合、正常页面能读、旧资产不被覆盖，以及确实没有模型调用。组件测试和固定剧本展示通过，不等于真实 Qwen 输出质量通过。本轮先做好账号认识、候选和已发布笔记讨论，尚未给四个账号各自补创作改稿示例。
