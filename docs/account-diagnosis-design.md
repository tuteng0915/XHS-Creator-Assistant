# 账号诊断：认识我的账号

## 2026-10-11 跨篇归纳是核心价值，不是要消除的行为

用户进一步明确：账号分析必须能跨篇泛化。此前减法实验不能被误解为退回逐篇摘要或放弃账号认识。最新任务方向是，从不同作品中概括作者共同的观察角度、判断方式与表达优势；同一关切在不同题材中可以有不同表现，不要求每篇采用同一措辞、顺序或结构。合理、积极的编辑判断与比喻可以保留，允许例外，不把“概括”本身当质量问题。

仅区分两件事：整体认识可以归纳，举例中的人物、经历、措辞和位置不能改写或移植。比如某账号多篇都在解释适配条件，足以概括它擅长帮助读者作选择；并不意味着每篇内部都有同一套利弊段落。固定六栏和统一 text/noteIds 协议不变，不增加分类或逐句审查字段。

人工验收收拢为三项：归纳有没有解释力、作品例子是否准确、下一篇建议是否有用。局部位置误读、输出协议失败和审美偏好分别记录，不将任一种问题笼统归因于“跨篇泛化”。当前实测／接入状态以状态文档本轮记录为准，下节记录的是上轮候选决定。

候选现为 v7.1，系统提示 1,430 字符，仍为一次 PROFILE 与相同六栏协议。四档最终一轮均完整生成，Ag／一粒鱼的共同判断方式更清晰；QSheep／秀才各残留一处具体素材串用，因此尚未替换 v5.3.1 默认。下游兼容已补齐：旧草稿／选题参考可读取新表达特点与下一步建议；非空旧字段优先，Pydantic 补出的空结构不作为有效素材，也不要求模型重建旧重复字段。

## 2026-10-11 减法方案：实现候选，尚未切默认

用户指出逐轮增加分类、片段和细则加重模型上下文，同意先做同样本对照，有质量收益再替换。新的设计方向是：模型负责少数具体的编辑判断，程序负责稳定栏目、笔记来源和表现统计；不要求模型给每篇建立结构分类或逐句标注。短示例只教反馈口吻，不使用四账号事实。

候选 `account_report_lean.py` 保留完整原标题／正文与本轮 n 编号，移除句段目录、结构枚举和逐句引用协议。输出六栏统一用 `text/noteIds`，映射到既有账号印象、关键词、内容价值、优势、表达方式与下一步；页面中的笔记表现仍由程序计算。笔记级来源显式存为 `{noteId, scope:"note"}`，只说明这条判断参考了哪篇，不伪造原标题引文、不视为语义已核验；旧逐字引用照常读取。建议可减少，不要求找缺点或补戏剧冲突。

四档案两轮共 8 次 `qwen3.8-max` 对照后，候选最终系统提示 1,073 字符，较当前默认 3,722 减少约 71%；第二轮 4 份均通过结构和来源检查。但一粒鱼仍归纳不存在的共同代价，Ag／秀才仍将某篇解释套到另一篇，QSheep仍有拔高。**质量门槛未过，不接入默认**；`ModelCallService` 仍使用下节 v5.3.1，新增测试锁定这个事实。保持旧默认不代表它已无质量问题，只表示这次实验不足以支持替换。

本轮当时发现的旧草稿读取兼容缺口已在后续 v7.1 迭代补齐，见顶部；没有让模型重复输出两套字段。新单助手创作引用整体报告不受此影响。完整失败、用量和验证见状态文档；不继续通过增加禁令或重复四档调用来宣称质量提高。

## 2026-10-11 固定报告模板与来源契约

本节记录仍在使用的旧默认方案；后续设计方向以上面的减法方案为准。用户此前确认主要通过 prompt、必要的分阶段任务和回答模板稳定质量。当前默认提示为 `backend/app/services/account_report_prompt.py` 中的 `account-report/2026-10-11-editorial-template-v5.3.1`。下表定义内容任务，映射到现有报告字段，不要求前端增加六张卡片。

| 部分 | 要回答的问题与句式骨架 | 篇幅／字段 |
| --- | --- | --- |
| 账号印象 | “你主要写【并列题材】。其中，【已有表达特点】，能帮助读者【具体理解或判断】。” | 约 60 字；`summary`；另给 3～5 个关键词 |
| 内容方向 | “【题材】：【这些作品持续回答的具体问题】。”不同题材并列，不强行统一 | 最多 3 项 `recurringThemes`；每项至少两篇 |
| 具体优势 | “在《【代表作】》里，你【具体做法】，让读者【阅读价值】。适合继续用在【同类内容】。” | 2～3 项 `strengths`，每项约 60 字 |
| 标题与开头 | 逐篇拆解原标题；用“连续原句—具体手法及作用—同类内容如何沿用”解释开头、措辞、节奏、称呼或转折 | 最多 2 项 `titleReadings`、3 项 `expressionReadings`；每项 1～3 个短原句 |
| 正文组织 | 先辨认行文推进、并列比较、重复模块；混合文章可只分析一个明确局部，不硬套时间线 | 一篇代表作的 `structureReading`，2～5 单元，明确整篇／局部范围；也可为空 |
| 下一步建议 | “下次写【已有题材】时，可以【一个编辑动作】，让读者【更容易理解、判断或感受什么】。” | 1～2 项 `nextMoves`，各带来源与原作做法 |

模板统一回答动作，不统一账号观点。建议应回答下一篇准备什么内容、继续解决哪个问题、保留哪种组织方法，不退化成日记、自我观察或“列三个动作”的训练，也不必先诊断原文有缺点。总量 600～900 字是生成目标，不截断旧报告、不为凑字数补栏目。

### 参考旧好结果，不照搬旧问题

只读回看 QSheep 2026-09-11 报告（`ac2933dd-b9ac-45ae-a9a4-380460464c79`），冻结当时的 20 篇输入。值得恢复的是“题材—标题承诺—内容推进—下一篇方向”的连续判断：例如《中传大三|专业第一，我为什么放弃保研》的成绩与选择反差，以及从外部评价转到自己判断的推进；不是恢复未经验证的流量归因或将所有生活记录工具化。

旧 20 篇和现在最近 5 篇的题材不同，不能把样本差异都归因于 prompt。正式分析仍只读用户选择，不自动补进代表作。人工验收分别判断题材准确、写法具体、建议保持原作目的、文字好懂；引用存在与 JSON 合法不替代这些判断。

### 不可答边界（集中写入提示，不重复展示给用户）

- 可以解释潜在阅读价值、提出明确编辑判断；不能宣称已证实的受众心理、传播原因或账号趋势。
- 不补没读到的图片／视频、正文和结尾，不分析未选篇目。
- 不合并不同笔记、不同申请人、引用者与作者的经历；建议不编新数字、对白、身体反应或个人故事。
- 不把题材拔高成统一理论，不让所有生活记录变教程；不诊断原作不存在的问题。
- 信息不足就省略该项，其他有价值部分照常回答，不为了模板凑数。

### 执行与模型选择

保留一次 PROFILE 请求，任务内依次辨认题材与写法、选择代表作、填入模板。本轮试过“精读→编辑”和整稿复评，第二步仍放大术语、把内容决策变成训练，未证明独立收益，已撤掉这些路径；以后只有收益明确才增加轮数。

输入 `account-reading-input/v3` 使用本轮局部 `n1/n2…` 和可逆正文片段 `b1/b2…`，保留全部已选文字。模型不抄长平台 ID，不接收互动指标与排名，表现仍由程序单独计算、展示。`source-led/v3` 输出在后端恢复稳定 ID 和原文，标题片段必须来自同一原标题且顺序正确；未知／歧义不猜测。新结果编译为已有展示字段，旧无版本／v1／v2 历史不回写、不重生成。

正文的 `kind` 为 `narrative`（行文推进，也含论述）、`comparison`（并列比较）、`repeated_blocks`（按对象重复展开）。各单元通常用同篇 1～4 个关键片段定位，但长段允许更多真实引用，硬上限为该篇可用片段数，不截取真实依据。单元内和单元间严格遵循原文顺序，不重复、交叉或用标题代正文。`scope=section` 必须提供局部名称；`whole_note` 需在阅读时保留真实落点，但编号顺序本身不能证明全篇覆盖。编译后 `viralStructure` 保留旧 `name/steps`，附可选 `kind/scope/scopeLabel/overview`；旧输出不增加空元数据。页面将比较／重复模块显示为圆点列表，行文推进与旧结构仍为编号列表，概览和局部标签直接可读。

表达观察按 `examples → kind → technique → application` 输出；正文按 `units → kind/scope → overview` 输出。来源先于解释，不在示例顺序上诱导先写抽象手法再寻找依据。例子用 `noteId/fromExcerptId/toExcerptId` 指定同篇连续正文，程序按原文顺序回填两端及中间文字，保留排版；通常 1～2 个片段，最多 6 个且总计 600 字，不截取或重写。这样连续自问、长短句对照不再受单句切分限制，模型也不再自行抄写或加入省略号。标题、未知／倒序／重叠范围或超限不通过；较早 v3 的 `excerptId/quote` 格式保持原有单片段、100 字逐字核验，不自动放宽旧引文。

先归一稳定笔记 ID 再判断单篇／多篇：单篇写“《…》的写法”，多篇只说所引作品中都可见，不由程序提升成整个账号的惯用习惯。`opening` 编译为 `hookStyles`，其余编译为 `voiceFingerprint`；前端标题为“开头写法”。新字段与非空旧字段双写拒绝，不静默覆盖。原句字面存在、编号顺序正确，都不能证明称呼对象、手法作用、结构种类和开头位置判断正确，必须另做语义审阅。

标题展示直接采用“原标题拆解＋按顺序的片段／作用”，不再额外让模型起一个可能与片段顺序矛盾的总括公式。v3 也允许短标题只有一个等于完整原标题的片段，显示“原标题解读”，不为了拆解凑两段；v1/v2 仍保持原规则。这个确定性简化保留原始响应用于审查，不更改旧报告。若模型把已知报告字段误放在 `profile` 外层，或把 nextMoves 错放进 structureReading，只在新版协议中无冲突归位后再核验，不丢失正文结构或建议，不猜测相互冲突的值。

用户根据同模板对照选择账号报告单独使用 `qwen3.8-max`（非思考模式）。`QWEN_PROFILE_MODEL` 只覆盖 PROFILE，其他操作继续用 `QWEN_MODEL`；显式空值可继承总模型。完整实测、实际用量与剩余问题见 `status-and-todo.md`，不将换模型的收益说成模板独自解决了全部问题。

## 产品问题与边界

### 2026-10-08 结果阅读层改版

当前问题：API 已返回结构化结果，但页面把多数结论平铺成同等权重的彩色卡片，分析范围也插在正文中间。第一轮只改 React 呈现，不改模型提示、字段、筛选或已保存结论。

- 首屏为账号概要、关键词与原顺序前三项优势；剩余优势可展开，数量上限仅用于初始显示，不是重新排序或删除结论。长句原文不做语义截断。
- 内容方向、读者价值、表达特点、近期变化和鼓励分别按需展开；无有效内容不留空栏。依据与历史引用继续可打开，正文始终取当次快照。
- 笔记表现采用标题／日期与指标／名次对齐的列表；切换指标、并列名次、缺失值与缺正文行为不变。分析范围、时间等元信息收在末尾。
- 用灰色分隔、留白与 14px 正文／16px 区块标题建立层级，蓝色留给交互；不叠渐变底和多层边框。窄屏允许换行，不能隐藏原文。
- 新版无旧内容归纳时不显示空折叠项；旧格式报告仍可读。未知结果的公开展示不直接倾倒 JSON，开发视图保留原始诊断。

预计修改 AccountPortraitView、AccountPerformanceView、ProfileView／结果 fallback 及相关样式、组件测试。验收包括初始层级、所有展开与依据、指标选择、长文本／缺字段／旧报告、390px 与桌面布局。只读核对四账号已有报告；缺少新版结果的账号按实际旧格式检查，不编造模型结果、不重新请求 Qwen。

## 改造前的断点

改造前的 `profile` 结果包含内容支柱、标题公式、开头钩子、惯用结构、风格指纹和高低表现对比；画像分析与评论痛点分析并行，之后生成选题。范围选择和 AnalysisRun 输入快照已经存在，可以复用。断点在于，模型主要读取整理成文本的历史笔记，结果中的支柱、公式和“共性”没有稳定的 `noteId` 依据；页面也不能从结论直接跳到原笔记。原资产有逐条 `publishedAt`，但派生给画像模型的笔记文本没有保留日期。`voiceFingerprint` 会生成、供下游使用，却未在诊断页面呈现供创作者核对。旧 prompt 对“标题｜数据｜爆/平/差”的条件描述还保留着原型时期的输入格式，而小红书派生笔记并不是这种格式。

这些问题不要求立刻改写 LangGraph。下一轮先补确定性的数据层和可核验的输出契约，再调整提示词和页面。旧 `profile` 结构仍可渲染；新运行采用带版本标记的新结构，不能拿新校验规则拒绝打开历史运行。

## 结果数据契约

以下是完整目标契约，部分字段已落地，不能将整张表当作当前 API 响应。新结构作为 `AnalysisRun.stageResults.profile` 的版本化内容保存；不另建泛用分析表。数值、范围、缺失情况和原文引用由后端从输入快照计算或核验，不能让模型自行填写。模型只归纳需要理解文本的维度，并明确区分“观察”“解释假设”和“下一步试验”。

| 对象 | 必要字段 | 生成与约束 |
| --- | --- | --- |
| `coverage` 分析依据 | `selectedNoteIds`、`selectedCount`、`availableCount`、`snapshotAt`、可选 `sourceFetchedAt`、`dateRange`、`missingDateCount`、各互动指标的缺失数、`capturedCommentCount` | 后端确定性计算。快照时间与可获得的采集时间分开，均不冒充笔记发布时间；所选范围与实际 ID 一致。 |
| `noteObservations[]` 笔记观察 | `noteId`、标题、发布时间或 `null`、类型、原始互动数、所选样本内相对位置、`theme`、`readerValue`、`openingPattern`、`contentForm` | 一条笔记一条观察。前五类事实来自快照；后四类是模型标注，可以为空或“难以判断”。相对位置要说明比较口径，不生成脱离样本的“爆/平/差”标签。 |
| `portrait` 账号画像 | 一句话定位、`recurringThemes[]`、`readerValue[]`、`expressionPatterns[]`、`voiceFingerprint[]` | 每项归纳包含 `statement`、`supportingNoteIds`、`counterexampleNoteIds`、`basis` 和 `certainty`。少量样本不得强行写出稳定特征；“作者经历”必须来自原始材料，而非评论者或模型推测。 |
| `performanceObservations[]` 表现差异 | `observation`、`comparedNoteIds`、实际指标、`possibleExplanations[]`、`otherExplanations[]`、`certainty` | 观察用中性描述，例如“这两条在所选笔记中收藏数较高”；原因只能标为假设。没有可比笔记时允许为空，并说明不足。 |

`basis` 至少区分 `source_fact`（原始材料直接可见）、`cross_note_interpretation`（跨笔记归纳）和 `hypothesis`（待验证解释）；`certainty` 用“证据较充分 / 有限 / 不足”，并同时显示样本量与依据，不给没有标定过的精确概率。标题示例应引用真实笔记标题，或者明确标为生成示例。`noteId` 必须属于本次选择范围，引用片段必须能在该笔记标题或正文中找到；评论证据保持其所属 `noteId`，有原始 `commentId` 时使用它，否则只用运行快照内稳定的序号定位，不能把读者经历写成作者画像。

选题仍是独立下游产物。新账号画像可以供现有选题生成使用，但在完成依据核验之前，旧字段和消费者的兼容映射必须保持；本设计不要求把全部 `noteObservations` 再次传给每个模型节点。建议先让选题只读取经过核验的画像摘要、相关评论痛点和明确的待确认信息。诊断结果展示“探索选题”入口，生成的 Topic 继续进入选题库；选题标题、正文和 AI 创作助手不在本轮重设计。

## 页面结构与交互

诊断页继续保留简洁的范围摘要、调整范围与开始分析。结果加载后，第一屏依次呈现分析依据卡、一句话账号画像、三个以内的主要内容方向和主要读者价值。没有足够证据时，用“目前看不出稳定方向”替代凑满三个标签。页面不重复堆放大标题和解释性副标题；术语面向创作者，例如“这份分析看了 10 条笔记”，不显示 `stage`、`run` 或 `noteId`。

第二层是“从哪些笔记看出来”：每条画像结论可以展开支撑笔记及不符合它的笔记，复用“我的笔记”的封面、正文和评论详情浏览；点击不改变分析范围或运行快照。表现差异使用实际数字和采集时间，并在观察下单列“可能的原因”，明确不是结论。近期变化仅在有可靠日期和足够可比笔记时显示；其他情况给一句缺失说明，不留空白图表。风格指纹也放在这里供用户核对，不让隐藏字段独自驱动后续创作。

页面末尾才提供“基于这份诊断探索选题”。选题建议可带回支持它的画像结论，但仍作为创作提议，不混入账号事实。分析历史详情沿用相同结果页，并显示当次选择范围、时间和原始输入；旧运行走旧版结果渲染。部分阶段失败时，已成功的画像或评论结果继续可读，清楚标记哪些部分没有生成。

## 验证方法与实施顺序

第一步只补确定性整理：由选中 ID 生成覆盖率、逐条日期与指标、缺失统计、样本内排序及可比范围；修正派生历史笔记不含发布时间的问题。测试最近 10 条、时间范围、手选、缺日期、无评论、重复标题以及刷新后重开历史运行。排序可作导航，不把互动总数机械压成单一“质量分”。如果仅有 4 条笔记，允许输出有证据的观察，但不强制形成“高表现共性”。

第二步定义并校验新版结构化输出：所有指标必须与快照一致；所有引用的笔记和评论必须属于当前账号与本次选择；引用文字须逐字存在；无依据的关键结论不能进入第一屏。字面匹配只能证明原文存在，不能证明推理成立，因此还要用人工审阅样本检查“证据是否真正支持结论”。模型失败时保存阶段错误和已成功部分，不用空白画像假装成功。

第三步调整结果页，先让每条结论能打开原笔记，再上线新版画像和表现差异。用现有 4 条和 20 条样本做回归，再准备缺日期、极端单篇高互动、评论稀少和选中子集的反例。验收重点是：显示数字与输入快照完全一致；每条第一屏结论可追溯到所选笔记；观察与推测在文案和数据结构上分开；旧分析历史照常打开；切换账号绝不串入另一账号的笔记。邀请产品经理盲审少量结果，逐条标记“有据、具体、过度推断、缺重要反例”，并记录争议，而不是仅凭模型 JSON 合法或页面好看判定质量。

最后才优化下游选题，让选题来源能指向已核验的账号画像。若后续能取得曝光或同内容的可控标题测试，再考虑点击率或标题效果分析；在现有数据条件下不加入流量预测、所谓“爆款概率”或因果口吻。这一阶段也不改受众分析与模拟，不新建版本表，保留旧输出字段与历史结果的兼容。

## 方法依据

这不是把其他平台的内容规律照搬到小红书。文化产品的实验显示，社会影响会放大表现差距，也增加结果的不可预测性，因此“高互动笔记的共同点”不足以单独证明成功原因：[Salganik、Dodds 与 Watts 的实验](https://pubmed.ncbi.nlm.nih.gov/16469928/)。标题效果的较强证据来自同一内容在可比曝光下进行的随机测试；[Upworthy Research Archive](https://www.nature.com/articles/s41597-021-00934-7)记录了这种实验所需的标题、曝光和点击数据。我们当前没有对应条件，所以把观察、解释假设和下一步试验分开，是方法上的约束，不是对小红书效果的外部验证。
