# 作者要求为什么仍会变成经历：同稿回放

2026-10-17，开发工作树候选；未部署、提交或推送。用户要求继续解决“很多应届生跟我说”，使用同一错误稿和确有交流经历的正例，不以删除真实经历换取安全。

## 定位：两层混淆，不是缺一句禁令

一粒鱼冻结请求原话包括：

> 开头回应觉得自己没做过大项目的应届生，保留原文直接、具体、讲实际判断而不是堆能力词的口吻。

请求同时明确说“不编我的新经历”。但旧编辑输入仍把完整 user 对话放在 creatorDialogue 中，与原文共同作为证据。前轮要求编辑给 basis 时，它曾把“作者要求开头回应觉得自己没做过大项目的应届生”作为保留虚构对话的依据。**谁下达了要求，不等于要求中的一切都在报告事实。** 这是输入资格上的缺口；它是有回执支持的错误判断，不是对模型内部思维路径的确定证明。

本轮第一条件把作者陈述独立摘录后，实际返回 facts=[]，没有把应届生写作对象当经历；但编辑仍对错误开场给 keep。因而还有第二层：**把叙事开场当普通表达，没有核对它实际上声称发生过交流。** 输入隔离本身不足以解决。

## 修改

1. 正文候选生成后，独立准备作者自述事实。此步骤不看候选稿、账号分析、助手旧回复或写作者的自证理由，只看真实 user 消息。只摘连续原话及对话索引，保留主体、否定和限定；“保留我去年和家人长聊的经历”中内嵌的自述仍可摘取。程序核对引文确实存在于该条作者消息。它不代表外部核实，也不能由字面匹配保证语义提取永远正确。
2. 事实编辑不再接收原始写作要求。合格来源目录只包括原有原文／稿件和上述作者陈述，来源有稳定引用 ID；旧分析解释仍不能成为经历证据。
3. 句子编辑协议区分具体事实 event 与观点／建议 opinion。保留 event 时须提供合格来源的逐字片段；找不到依据则局部撤回事实增量，保留原句的表达作用。opinion 无需引用，不统一弱化为“可能”。程序能核对来源资格和字面存在，**不能证明引用支持了完整语义，仍可能误分类**。
4. 仍是同一创作助手和现有模型传输，不新增可见团队、通用运行时、自动重试或别家回退。通常正文请求由原来的“起草＋编辑”两次变成“起草＋陈述准备＋编辑”最多三次；没有正文候选不启动后两步，没有作者对话则只做编辑。未采用稿不写 Topic。
5. 陈述准备失败时，不把空事实集冒充成功去删除真实经历：停止编辑，保住稿件并沿用“事实校订未完成”提示。编辑缺句／失败也不整篇拒收；记录失败阶段、原始输出、原稿、局部修改和分步 usage。完成仅表示检查覆盖，不是事实认证。

起草系统提示本轮未继续加长。新提示用于一个独立的输入投影任务；编辑改的是判定协议与引用资格，不是把“别编经历”再重复几遍。

## 样本：坏稿不换，正例有来源

| 样本 | 出处与用途 |
| --- | --- |
| same_bad_draft | 原封不动读取一粒鱼 `creator-fact-edit-yiliyu-20261017/initial-deepseek.json` 的 `modelMetadata.factEdit.originalOutput`；整篇正文、标题和来源都不替换，不重新生成更容易的坏稿。 |
| source_communication | QSheep 原笔记《如果你还在摇摆保研出国，分享三个判断逻辑》确有“在去年这个阶段，我和家人长聊了几番”。用此原话和一句观点构造诊断短稿，保留冻结原文上下文。**不是先前模型生成的完整好稿。** |
| mixed_request_communication | 同一真实原话移入“开头回应犹豫的读者。保留这段真实经历：……”的诊断消息，编辑输入移除原笔记，以检查混合要求中的事实仍能被摘取并保留。**这是受控测试消息，不是作者实际发过的新消息，不写入产品历史。** |

## 两条件的实际结果

### 条件 A：仅隔离作者陈述，失败保留

第一轮 6 次 DeepSeek 请求，5,612 tokens。

- 错误稿：摘录正确为空，但 23 个候选句（含标题）全部 keep，**没有修好**；9.407 秒，其中摘录 6.731 秒、编辑 2.675 秒。
- 原文交流正例：3 句全部保留；1.596 秒。
- 混合要求正例：真实原话成功摘录，3 句全部保留；2.087 秒。

三份生产契约都通过，不把它等同于事实通过。记录未覆盖或回写为成功。

### 条件 B：隔离陈述＋事实保留引用协议

第二轮仍用完全相同三稿，6 次请求、6,665 tokens。

错误开场：

> 很多应届生跟我说，简历上只有普通实习，没做过什么大项目，是不是就没什么可讲的。

实际局部替换：

> 很多应届生会问，简历上只有普通实习，没做过什么大项目，是不是就没什么可讲的。

编辑明确判为 event，理由是原句“跟我说”主张具体对话经历、来源未支持。**只修改这一句，其他正文和标题逐字保留**；没有按禁词删掉所有“我”或所有交流句，也没有整篇改写。原文中候选人做配置模板、与产研核对等动作分别有来源引用而保留；ownership观点、三件行动建议和AI边界没有被统一弱化。

真实正例在两种来源形态下均完整保留：

> 在去年这个阶段，我和家人长聊了几番。想清楚路径，不能只靠一时的冲动。

原文正例引用所选原笔记；混合要求正例引用 `statement:0`，其 text 正是从要求内摘出的真实原话。第一句 event 有依据保留，第二句 opinion 不要求引用、原样保留。三份生产契约再次通过。

## 没有解决的部分

- “很多应届生会问”去掉了作者亲自接待，但“很多”仍是未证实的人群概括。不能宣称已彻底消除推断事实化，也没有自动手改回执把它包装成完全理想的“如果你……”开场。
- 第二条件只各测一次，不能估计长期命中率；输入与协议同时变化，不能排除 sampling 差异或声称引用协议单独贡献全部收益。
- 本轮正例是短稿，不代表长稿中的每条真实经历都不会被误删。引用存在不保证主体一致；event／opinion 和原话提取仍依赖模型判断。
- 稿件作为原有来源的资格、历史评论原话尚未全面覆盖的问题仍在，不由本轮自动解决；未验证新起草／采用／手动保存整条浏览器流程。
- 多一次调用有真实等待成本，出现 43.660 秒增量，**尚不适合称作已完成低延迟上线**。开发候选保留，不自动部署给用户。
